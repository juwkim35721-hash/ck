# MASTER_GUIDE — SK하이닉스 해커톤 운영 가이드

이 문서 하나로 **설치 → 담당자 DM으로 요구사항 확정 → 명세 동결 → 구현·검증 → 보고서 → 후속 6문항 대비 → 제출**까지 진행합니다. 복붙할 프롬프트는 [`prompts/`](../prompts/README.md)에 단계별 폴더로 나뉘어 있고, 터미널에서 `python3 sk/scripts/help.py`로 바로 꺼내 볼 수 있습니다. 공식 대회 공지와 과제 문서가 항상 이 가이드보다 우선합니다.

## 0. 약속 — 모든 것은 과제 루트에서

| 약속 | 명령 |
| :--- | :--- |
| ① 과제 루트에서 클론한다 | `git clone https://github.com/juwkim35721/sk sk` |
| ② 과제 루트에서 설치한다 | `python3 sk/scripts/install.py` |
| ③ 과제 루트에서 Codex를 실행한다 | `codex` |

**과제 루트**는 시험이 준 실제 과제 폴더(README·소스·데이터가 있는 곳)입니다. 설치 프로그램은 `sk` 폴더의 **부모 폴더를 과제 루트로 간주**하며, 다른 위치에서 실행하면 이동할 경로를 알려 주고 멈춥니다.

```text
<과제 루트>/
├── README.md, src/, data/ …     ← 과제 파일 (Codex가 구현하는 대상)
├── sk/                          ← 이 저장소 (도구. 과제 코드가 아님)
│   ├── prompts/0-start … 9-qa/  ← 단계별 전략 프롬프트
│   ├── skill/sk-*/SKILL.md      ← 스킬 원본 38개
│   ├── templates/  snippets/    ← 템플릿 3종, 스니펫 2종
│   ├── scripts/install.py, help.py
│   └── work/                    ← 작업 노트 (설치 시 생성, git에 안 올라감)
├── AGENTS.md                    ← 설치 시 SK-KIT 관리 구역이 추가됨
└── .agents/skills/sk-*/         ← 설치된 스킬 (Codex가 자동 인식)
```

설치가 하는 일은 네 가지뿐입니다.

1. 과제 루트 `AGENTS.md`에 `SK-KIT:BEGIN/END` 관리 구역을 추가합니다. 기존 내용은 그대로 두고, 바뀌는 파일은 먼저 `sk/.install/backups/`에 백업합니다.
2. `sk/skill/`의 38개 스킬을 `.agents/skills/`로 복사합니다. Codex는 실행 위치의 `.agents/skills`를 읽습니다.
3. 과제 루트가 git 저장소라면 `.git/info/exclude`에 `sk/`, 설치한 스킬, 새로 만든 `AGENTS.md`를 넣어 `git status`를 깨끗하게 유지합니다. 이 설정은 로컬 전용이라 커밋되지 않습니다.
4. 작업 노트 폴더 `sk/work/`를 만듭니다.

네트워크 사용, 패키지 설치, Codex 설정 변경은 하지 않습니다.

## 4. 핵심 — 담당자 DM으로 요구사항·제약을 확정하고 명세를 동결한다

구현 품질은 코드를 쓰기 전에 거의 정해집니다. 모호한 규칙(결측값 처리, 동점 정렬, 규칙 충돌 우선순위, 출력 형식)을 추측으로 구현하면 테스트·채점 기준과 어긋나고, 나중에 고치려면 여러 파일을 다시 건드려야 합니다. 그래서 **1·2단계에서 질문 → 답변 기록 → 명세 정리 → 확인 → 동결**을 한 번에 끝내고 구현에 들어갑니다.

```text
1.1 요구사항·제약 추출 ─┐
1.2 모호성 G 목록 ──────┼─→ 1.3 DM 질문 설계 ─→ [내가 DM 전송] ─→ 1.4 답변 기록·해석 ─┐
2.2 데이터 계약(대기 중) ┘                                                            │
                     ┌────────────────────────────────────────────────────────────────┘
                     └─→ 2.1 SPEC 통합 ─→ 2.3 수용 테스트 표 ─→ 1.5 재진술 확인 DM ─→ 2.4 게이트(동결)
```

### 4.0 한 번에 돌리는 질의 루프 (1.0 clarify-loop) — 권장

1.1~1.5를 하나씩 부르는 대신 `$sk-clarify-loop` 하나로 **스캔 → 질문 → 답변 반영 → 후속 질문**을 라운드로 반복할 수 있습니다. 세부 규칙은 1.1~1.5 스킬을 그대로 따르고, 루프는 라운드 진행과 판정만 맡습니다.

```text
R0  python3 sk/scripts/help.py 1.0 -p     → 과제 전체 스캔, R·C·G 목록, 첫 DM(최대 3문항)
    [내가 DM 전송]
Rn  $sk-clarify-loop + 답변 원문 붙여넣기    → 원문 보존, P 변환, 영향 재스캔, 파생 질문, 판정
    (판정이 '계속'이면 다음 DM 전송 후 Rn 반복)
끝  python3 sk/scripts/help.py 1.0 -p 4   → 마감: 남은 G 가정 전환, 구현 기준 요약 → 2.1
```

- **라운드 0 전체 스캔**: `sk/`·`.git`·`.agents`·의존성 폴더를 뺀 모든 파일을 역할(문서·데이터·테스트·진입점·설정 등)과 읽기 깊이(정독·훑음·제외+사유)로 분류해 `DISCOVERY.md`의 `## 스캔 커버리지`에 남깁니다. 문서·테스트·진입점·미구현 흔적은 반드시 정독합니다.
- **영향 재스캔**: 답이 오면 새 규칙의 필드명·상태값·경로로 과제 전체를 다시 검색해, 같은 규칙이 적용될 다른 위치와 반대로 기대하는 테스트·문서를 찾습니다.
- **파생 7점검**: 답변마다 경계(0·등호), 적용 범위, 출력 표현, 집계 영향, 규칙 순서, 예외, 시점을 확인하고 결과가 달라지는 것만 새 질문 후보로 올립니다.
- **판정**: 계속(질문할 H 또는 P0 결과를 바꾸는 M이 남음) / 확인(그런 질문이 0개, 재진술 DM 1회) / 종료(→ 2.1) / 병행 전환(동결 시각 도달, 구현하며 계속 질문) / 차단(제출물·P0 출력 형식 미정). `DM_LOG.md` 맨 위 `## 질의 루프 상태판`에 라운드별 숫자가 쌓입니다.
- **닫힘 기준**: 열린·질문 중·충돌 H 0개, 모든 P에 조건 → 동작·예시·근거, 문서↔P 충돌 0개, P0 요구마다 기대 출력을 손계산할 수 있음.
- **질문 수**: 총 질문 수·라운드 수 상한은 없습니다. 대신 메시지당 3문항, 앞 답이 오기 전 다음 묶음 금지, 매 라운드 가치 없는 질문(문서로 답이 있거나 결과가 안 바뀌는 것) 제거를 지킵니다. 라운드 5회·질문 15개마다 Codex가 수렴 점검(열림·닫힘 추세, 범위가 넓어지는지)을 보고하고, 계속할지는 내가 정합니다.
- **동결 시각(약 10:40)은 질문을 멈추는 시각이 아니라 구현을 시작하는 시각**입니다. 남은 질문은 되돌릴 지점이 있는 가정으로 두고 구현을 시작하면서 `병행 라운드`로 계속 묻습니다. 답이 가정과 같으면 확정, 다르면 `SPEC.md` 13절 변경 기록과 영향받는 테스트부터 고칩니다. 리뷰(약 12:00) 이후에는 H만, 제출 점검(약 12:35) 이후에는 새 질문을 보내지 않습니다.

### 4.1 무엇을 뽑아내나 (1.1 requirements, 1.2 ambiguity)

- **요구사항 R**: 기능, 출력, 비기능 요구. 기존 테스트가 기대하는 동작(암묵 요구사항)도 포함하고, 모든 항목에 `파일:줄` 출처를 답니다.
- **제약 C**: 유지할 API·함수 서명·출력 스키마, 지정 포트·`0.0.0.0`, 금지 라이브러리, 수정 금지 파일, 성능, 제출 형식.
- **필수 제출물**: 파일명·경로·형식. 보고서 위치도 여기서 확정합니다.
- **모호성 G**: 14개 범주(용어 정의, 결측, 이상치·경계 등호, 중복, 정렬·동점, 반올림·단위, 시간대·기간 경계, 규칙 충돌, 오류 처리, 출력 스키마·빈 결과, 규모, 범위, 권한, 제출 형식)로 훑습니다. 각 G에는 "A로 하면 결과가 X, B로 하면 Y"라는 구체적 차이와 영향도(H/M/L)를 적습니다. 데이터가 있으면 `data_audit.py` 수치(예: 결측 12행, 음수 3행)를 근거로 씁니다.

### 4.2 좋은 DM 질문 (1.3 dm-questions, 템플릿 `sk/templates/DM_QUESTION_TEMPLATES.txt`)

- **영향도 H만, 메시지당 최대 3개.** 문서·테스트·데이터로 답할 수 있는 것은 묻지 않습니다. 채점 방식처럼 담당자 업무와 무관한 질문도 하지 않습니다.
- **선택지형으로 묻습니다**: 상황 1줄 → 실제 예시(행·값) → 선택지 A/B(/C) → 제 제안과 이유 → "다른 기준이 있으면 알려주세요".
- 답변 형식을 안내합니다: "1-A, 2-B처럼 답해 주셔도 됩니다."
- 정중한 존댓말로 12줄 이내. 내부 ID(G3, R2)는 메시지에 넣지 않습니다.

```text
나쁜 예: 결측치는 어떻게 처리할까요?
좋은 예: sensor_log.csv의 temperature 값 중 빈 값이 12건, -999가 3건 있습니다.
        1) 이 레코드를 (A) 집계에서 제외할지, (B) status=ERROR로 분류해 포함할지 궁금합니다.
           제 제안은 A입니다(평균 왜곡 방지). 다른 기준이 있으면 알려주세요.
```

템플릿(`python3 sk/scripts/help.py dm`)은 범주별 질문 패턴 14종(P01~P14, 1.2 모호성 범주와 같은 순서), 상황별 메시지 형식 11종(M01 첫 묶음 ~ M11 재진술), 답변 뒤 파생 질문 문구(D1~D7), 과제 유형별 완성 예시(E1~E6), 나쁜 질문 고쳐 쓰기, 보내기 전 체크리스트로 되어 있습니다. Codex는 G의 범주로 패턴을, 상황으로 형식을 고르고 '채울 칸'을 실제 값으로 채웁니다. 패턴 문장을 그대로 보내지 않습니다. 메시지는 Codex가 코드블록으로 만들어 주며 `DM_LOG.md`에 M#으로 기록됩니다.

### 4.3 답을 기다리는 동안

질문한 규칙에 의존하지 않는 일을 합니다: [2.2 io-contract](../prompts/2-spec/2.2-io-contract.md)로 데이터 계약 작성, [0.3 code-map](../prompts/0-start/0.3-code-map.md) 보강, SPEC 초안 작성. 질문한 부분은 기본안을 가정 A#로 적고 **되돌릴 지점**(어느 함수·조건을 바꾸면 되는지)을 같이 남깁니다.

### 4.4 답이 오면 (1.4 dm-answers)

담당자 답변을 **원문 그대로** Codex에 붙여 넣고 `$sk-dm-log`를 호출합니다. Codex는 원문을 보존하고, 각 답을 테스트 가능한 규칙 P#("조건 → 동작", 예시 포함)으로 바꾸고, 영향받는 R·테스트·코드 위치를 표시합니다. "적절히", "알아서" 같은 답은 기본안을 정해 가정 A#(근거: 담당자 위임)로 남깁니다. 문서와 충돌하면 확인 질문 초안을 만듭니다.

### 4.5 명세 통합과 동결 (2.1 → 2.3 → 1.5 → 2.4)

- **2.1 spec**: `SPEC.md` 하나에 모읍니다. 맨 위에 10줄 이내 **한 장 요약**과 **구현 시 반드시 지킬 규칙 Top 5**. 충돌 해소 순서는 공식 문서 > 담당자 확정 답변 P > 기존 테스트·코드 동작 > 가정 A입니다.
- **2.3 acceptance**: 각 R의 수용 기준과 모든 P를 구체적인 입력·기대 출력의 테스트 표 T#로 바꿉니다. 기대값은 구현과 독립적으로 손계산합니다. 이 표가 구현·검증의 기준이 됩니다.
- **1.5 dm-confirm**: "제가 이해한 내용은 이렇습니다(목표, 핵심 규칙 3~5개, 출력 형식, 범위 밖). 이대로 진행해도 될까요?"를 10줄 이내로 보냅니다. 영향도 H 가정이 남아 있을 때 특히 중요합니다.
- **2.4 spec-gate**: READY / READY-WITH-ASSUMPTIONS / BLOCKED를 판정합니다. **시작 후 약 40분이 지나면 답을 기다리지 않고 READY-WITH-ASSUMPTIONS로 진행**합니다. 동결 이후 새 답변이 오면 `SPEC.md` 13절 변경 기록에 남기고 영향받는 테스트부터 고칩니다. 남은 질문은 [1.0 clarify-loop](../prompts/1-discover/1.0-clarify-loop.md)의 병행 라운드로 계속 묻습니다.

## 5. 계획 → 구현 루프 → 검증 (3·4·5단계)

```text
3.1 plan (슬라이스 S1..Sn, P0 먼저, 위험 실험 먼저) → 3.2 design (대안 A/B 비교 → DD#)
  └─ 슬라이스마다 반복 (4.0 build-loop 한 번 = 아래 한 바퀴):

     → 4.3 harden (관련 엣지 케이스) → 5.1 verify + 5.2 evidence (E# 기록)
     → 데이터 과제 5.3 / API 과제 5.4 / UI 과제 5.5
```

- **한 번에 한 슬라이스.** "전부 구현해 줘"라고 하지 않습니다.

- **증거는 실행으로만**: 테스트·명령을 실제로 실행한 결과만 E#로 기록합니다. 코드가 바뀌면 이전 증거는 STALE이 되어 다시 실행합니다.
- **엣지 케이스**(원본 가이드의 7대 범주): 결측·빈 값, 경계값·이상치·0 나누기, 타입·스키마 오염, 중복·멱등성, 동점 정렬, 권한·상태 전이(4xx), 서버 바인딩·경로. 현재 기능과 관련된 범주만, 담당자 정책 P#에 근거해 방어하고 회귀 테스트로 남깁니다.

### 5.0 한 번에 돌리는 구현 루프 (4.0 build-loop) — 권장

4.1 → 4.2 → 4.3 → 5.1/5.2를 슬라이스마다 따로 부르는 대신 `$sk-build-loop` 하나로 한 바퀴를 돕니다. 각 단계의 세부 규칙은 원래 스킬을 그대로 따르고, 루프는 단계별 게이트·멈춤 조건·판정만 맡습니다.

후속 서술형은 **AI·복붙 없이 문항당 5분**입니다. 그래서 제출 전, AI 사용이 허용된 시간에 **내가 만든 것을 내 말로 설명할 수 있게** 준비합니다. 남이 쓴 답을 외우는 것이 아니라 내 코드·결정·증거를 이해하는 작업입니다.

## 11. 프롬프트 꺼내 쓰기 (`help.py`)

```bash
python3 sk/scripts/help.py            # 단계별 전체 목록
python3 sk/scripts/help.py flow       # 권장 순서
python3 sk/scripts/help.py 1          # 1단계(발굴·DM) 목록
python3 sk/scripts/help.py 1.3        # 프롬프트 파일 전체 (이름도 가능: dm-questions)
python3 sk/scripts/help.py 1.3 -p     # 기본 프롬프트만 출력 (복사용)
python3 sk/scripts/help.py 1.3 -b     # 블록 목록 (심화·변형)
python3 sk/scripts/help.py 1.3 -p 2   # 두 번째 블록
python3 sk/scripts/help.py -s 동점     # 검색
python3 sk/scripts/help.py dm         # 템플릿 원문: dm / report / qa
python3 sk/scripts/help.py work       # 작업 노트 현황
```

프롬프트의 `<...>` 자리는 실제 값으로 바꿔 붙여 넣습니다. 첫 줄의 `$sk-...`는 스킬 호출입니다. 지원되지 않는 버전이면 첫 줄을 빼고 나머지 지시문만 붙여 넣어도 됩니다.

## 12. 설치 관리와 문제 해결

```bash
python3 sk/scripts/install.py --dry-run      # 변경 없이 계획만
python3 sk/scripts/install.py --check        # 설치 파일 상태 점검 (읽기 전용)
git -C sk pull && python3 sk/scripts/install.py   # 키트 갱신 후 재설치
python3 sk/scripts/install.py --uninstall    # 설치한 것만 제거
```

| 증상 | 해결 |
| :--- | :--- |
| `과제 루트에서 실행하세요` | 안내된 `cd '<과제 루트>'`를 실행한 뒤 `python3 sk/scripts/install.py` |
| `클론 폴더 이름은 sk여야 합니다` | 과제 루트에서 `git clone https://github.com/juwkim35721/sk sk`로 다시 받기 |
| `/skills`에 `sk-*`가 안 보임 | ① Codex를 과제 루트에서 실행했는지 확인 ② Codex 재시작 ③ 그래도 없으면 구버전 경로로 설치: `python3 sk/scripts/install.py --skills-dir codex` 후 재시작 ④ 스킬 호출 없이 프롬프트 본문만 사용 |
| AGENTS.md 관리 구역 표시가 손상됨 | 설치가 멈춥니다. `SK-KIT:BEGIN`/`END`를 한 쌍만 남기고 다시 설치 |
| 과제 테스트·린트가 `sk/`를 검사함 | `sk/`는 도구이므로 제외 옵션 사용(예: `--exclude sk`) |
| 설치 전 상태로 되돌리고 싶음 | `--uninstall`. 덮어쓴 파일의 원본은 `sk/.install/backups/<시각>/`에 있음 |
