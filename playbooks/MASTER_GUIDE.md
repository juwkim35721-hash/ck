# MASTER_GUIDE — SK하이닉스 해커톤 문제 해결 운영 가이드

이 가이드는 [juwkim35721/sk](https://github.com/juwkim35721/sk)의 **설치, 단계 선택, 실행·검증, 제출 준비**를 연결합니다. 상세 복붙 프롬프트는 [prompts/](../prompts/README.md)에 따로 두어 이 문서와 중복하지 않습니다. 대회 공식 안내와 실제 과제 요구사항이 항상 우선이며 AI 사용이 허용된 단계에서만 사용합니다.

## 1. 과제 시작 전에 구분할 세 가지

**준비 도구는 `~/sk`, 실제 과제는 시험이 지정한 폴더, 설치 키트는 기본 `/tmp/cofa-kit`**입니다. 클론 폴더 이름은 `sk`로 통일하지만, 과제 루트를 무조건 `sk`나 `~/workspace`로 가정하지 않습니다. `@README.md`를 선택할 때도 실제 과제 README인지 확인하세요.

모델·Codex 명령·시험 시각·감독 절차·공개 자료 활용 범위는 당일 공식 안내로 확인합니다. 이 저장소에는 공식 메일 원문이 없습니다. 허용하지 않은 도구를 설치하거나 버전을 업데이트해 문제를 해결하지 마세요.

모든 스킬은 저장소의 **`skill/` 한 폴더**에서 관리하고 호출 이름도 **`sk-*`**로 통일합니다. 이전 `cofa-*` 6개는 대응하는 세부 스킬에 병합했으며, 별도 중복 스킬로 설치하지 않습니다. `snippets/`, `templates/`는 원본을 유지합니다. 설치 위치인 `~/.agents/skills`, `~/.codex/skills`의 복수형은 Codex 검색 경로이므로 그대로 사용합니다.

## 2. 터미널별 시작 절차

### 터미널 2 — 준비 도구 설치와 프롬프트 조회

일반 셸에서 실행합니다. Codex 입력창에 셸 명령을 붙이지 않습니다.

```bash
cd ~ && git clone https://github.com/juwkim35721/sk sk
python3 ~/sk/scripts/install.py --workspace "$HOME/workspace"
```

두 번째 줄의 `--workspace`는 실제 과제 경로로 바꿉니다. 존재하지 않는 폴더는 설치가 거절됩니다. `sk`가 이미 있으면 지우지 말고 먼저 저장소를 확인하세요.

```bash
git -C ~/sk remote -v
```

설치는 로컬 파일만 복사합니다. 외부 스킬 다운로드, 클론 폴더 이동·삭제, Codex 업데이트는 하지 않습니다. 현재 하네스는 **과제 루트의 `AGENTS.md`**에 추가되며 전역 `~/.codex/AGENTS.md`는 덮어쓰지 않습니다. 기존 프로젝트 지시문은 유지하고 `SK-KIT:BEGIN/END` 관리 구역만 추가·갱신합니다. 변경 전 프로젝트 파일과 내용이 달라지는 같은 이름의 설치 파일은 키트 `backups/`에 먼저 보존됩니다. 관리 구역 표시가 손상·중복되면 자동 수정을 거절합니다.

설치 계획과 설치 후 파일 상태를 확인하는 명령은 다릅니다.

```bash
python3 ~/sk/scripts/install.py --workspace "$HOME/workspace" --dry-run
python3 ~/sk/scripts/install.py --check
bash /tmp/cofa-kit/help.sh workspace
bash /tmp/cofa-kit/help.sh list
```

`--dry-run`은 쓰기 없이 계획만 출력합니다. `--check`는 설치 기록의 해시를 비교하는 **검사 전용** 옵션입니다. 실제 Codex 인식·과제 동작까지 확인하는 명령은 아닙니다.

### 이전 버전의 중복 스킬 통합

저장소에는 `skill/` 아래 18개 `sk-*`만 남깁니다. 이전 스킬의 역할은 아래처럼 연결하고, 이미 포함된 절차는 반복하지 않습니다.

| 이전 스킬 | 통합 대상 |
| :--- | :--- |
| `cofa-start` | `sk-context`, `sk-define`, `sk-clarify`, `sk-plan` — 과제 유형·완료 기준·정책 질문·계획 |
| `cofa-eda` | `sk-data-contract`, `sk-data-validation` — 데이터 계약·실제 감사·독립 검산 |
| `cofa-design` | `sk-design`, `sk-implement` — 대안 비교와 구현 책임 분리 |
| `cofa-edge` | `sk-harden` — 관련 예외·경계·불변식 방어 |
| `cofa-verify` | `sk-verify` — 정상·예외 테스트와 변경 파일 검증 |
| `cofa-brief` | `sk-deliver`, `sk-retrospect` — 제출 문서와 사실 기반 설명·회고 분리 |

이전 버전을 이미 설치했다면 재설치만으로 기존 `cofa-*`가 자동 삭제되지는 않습니다. 해당 스킬까지 정리하려면 다음을 사용합니다. **배포했던 원본과 해시가 같고 추가 자료가 없는 이전 스킬만 백업 후 제거**하며, 사용자 수정본·추가 파일·심볼릭 링크는 보존하고 경로를 표시합니다.

```bash
python3 ~/sk/scripts/install.py --workspace "$HOME/workspace" --migrate-legacy --dry-run
python3 ~/sk/scripts/install.py --workspace "$HOME/workspace" --migrate-legacy
```

일반 새 설치에는 `--migrate-legacy`가 필요 없습니다. 수정되어 보존된 이전 스킬은 내용을 비교해 필요한 부분을 직접 통합한 뒤 정리하세요. 무관한 사용자 스킬은 이 옵션의 대상이 아닙니다. 예전 키트 내부의 `skills/`·`custom-skills/` 복사본은 자동 삭제하지 않지만 새 설치 경로나 스킬 검색 대상으로 사용하지 않습니다.

### 터미널 1 — 실제 과제 루트에서 Codex 실행

```bash
cd ~/workspace && pwd && ls -la && codex
```

폴더 이동이 실패하면 Codex도 실행되지 않습니다. 실제 경로가 다르면 그 경로를 사용합니다. 제공 버전이 지원하는 경우 Codex 입력창에서 다음을 확인하세요.

```text
/status
/skills
/model
```

`sk-context`, `sk-define` 등 신규 스킬이 인식되는지 확인합니다. 안 보이면 설치 파일과 실제 작업 경로를 확인하고 진행 상태를 정리한 뒤 Codex를 재시작합니다. `$스킬명` 호출이 미지원이면 프롬프트 맨 앞의 호출 부분을 빼고 같은 자연어 지시를 사용하세요.

기존 전역 하네스나 과제의 하위 `AGENTS.md`가 있으면 함께 영향을 줄 수 있습니다. 새로운 파일 하나를 설치했다고 모든 규칙이 바뀐다고 가정하지 말고, 적용 중인 상위·하위 지시와 충돌을 확인하세요. 기존 규칙을 자동 삭제하지 않습니다.

## 3. 기본 문제 해결 흐름과 전환 기준

모든 단계를 동일한 시간으로 실행하지 않습니다. **현재 병목을 풀고, 다음 단계로 넘어갈 증거를 얻는 것**이 목표입니다. 정의·정책·계약은 과제 복잡도에 따라 함께 처리하고, 구현·방어·검증은 작은 기능 단위로 반복합니다.

| 단계 | 사용 파일·스킬 | 다음으로 넘어갈 기준 |
| :--- | :--- | :--- |
| 00 환경·기준선 | [00-context](../prompts/00-context.md), `$sk-context` | 실제 루트·적용 규칙·실행 명령·기존 상태를 확인 |
| 01 문제 정의 | [01-define](../prompts/01-define.md), `$sk-define` | 필수 요구사항 ID, 수용 기준, 제출물과 비목표를 구분 |
| 02 정책 확인 | [02-clarify](../prompts/02-clarify.md), `$sk-clarify` | 결과를 바꾸는 정책은 답변 또는 명시적 가정으로 기록 |
| 03 데이터 계약 | [03-data-contract](../prompts/03-data-contract.md), `$sk-data-contract` | 타입·키·단위·시각·고유 키·오류 계약과 미확인 항목을 구분 |
| 04 실행 계획 | [04-plan](../prompts/04-plan.md), `$sk-plan` | 필수 수직 슬라이스·위험 실험·검증·제출 버퍼를 설정 |
| 05 최소 설계 | [05-design](../prompts/05-design.md), `$sk-design` | 선택 근거·수정 범위·인터페이스·실패 전략을 설명 |
| 06 구현 | [06-implement](../prompts/06-implement.md), `$sk-implement` | 요구사항 하나의 입력부터 출력까지 실제 실행 |
| 07 예외 방어 | [07-harden](../prompts/07-harden.md), `$sk-harden` | 관련 반례에 최소 방어와 회귀 테스트를 연결 |
| 08 독립 검증 | [08-verify](../prompts/08-verify.md), `$sk-verify` | 기대값·실제값·요구사항별 통과/실패/미검증을 확인 |
| 09 반증 리뷰 | [09-review](../prompts/09-review.md), `$sk-review` | 근거 있는 위험을 심각도·위치·재현으로 보고 |
| 10 제출 준비 | [10-deliver](../prompts/10-deliver.md), `$sk-deliver` | 필수 파일·재현·저장·민감정보·잔여 결함을 점검 |
| 11 설명·회고 | [11-retrospect](../prompts/11-retrospect.md), `$sk-retrospect` | 실제 코드·테스트에 근거해 선택·동작·한계를 설명 |

터미널 2에서 번호로 문서를 열 수 있습니다.

```bash
bash /tmp/cofa-kit/help.sh 01
bash /tmp/cofa-kit/help.sh 06
bash /tmp/cofa-kit/help.sh 08
```

문서의 `[과제 루트]`, `[남은 시간: 분]`, `[담당자 답변]` 등을 실제 값으로 바꾸고 기본 프롬프트부터 사용합니다. 심화 프롬프트는 모호성이 남거나 반례를 더 확인할 필요가 있을 때 선택합니다. 없는 답변과 결과는 쓰지 않습니다.

## 4. 과제 유형별 우회 경로

**데이터 집계·설비 로그·이상탐지**라면 03 단계에서 단위·시각·결측·중복 기준을 확인하고, 08 단계에서 [93-data-validation](../prompts/93-data-validation.md)을 추가합니다. 원본과 전처리 후 행 수가 다르면 포함/제외 규칙으로 차이를 설명합니다. ML은 실제 과제에 있을 때만 누수·분할·평가 지표를 확인합니다.

**API·업무 규칙**이라면 03 단계에서 기존 메서드·경로·입출력 계약을 읽고 [94-api-contract](../prompts/94-api-contract.md)로 본문·오류·상태 전이·중복 요청을 검증합니다. HTTP 200만으로 업무 결과를 판정하거나 인증 정책을 임의로 바꾸지 않습니다.

**UI·대시보드**라면 필수 사용자 흐름을 구현한 뒤 [95-ui-smoke](../prompts/95-ui-smoke.md)로 로딩·빈 값·오류·긴 입력·키보드 접근을 봅니다. 브라우저를 실제로 실행하지 못했으면 화면 검증을 완료했다고 쓰지 않습니다. 웹 과제에서만 지정 포트와 `0.0.0.0` 바인딩을 확인합니다.

**레거시 버그 수정**이라면 00 기준선 → [90-debug](../prompts/90-debug.md) → 06 최소 수정 → 08 회귀 검증 → 09 리뷰를 짧게 반복합니다. 전체 코드를 다시 쓰는 대신 같은 재현 명령을 통과시키는 것이 우선입니다.

## 5. 시간 관리와 반복 오류 대응

180분 과제라면 다음을 연습용 배분으로 사용할 수 있습니다. 공식 시험 시간을 확정한 표가 아니므로 실제 남은 시간에 맞춰 조정합니다.

| 남은 시간을 쓰는 구간 | 권장 작업 |
| :--- | :--- |
| 시작 후 0~25분 | 환경·요구사항·정책·데이터 계약 확인 |
| 25~40분 | 위험 실험·계획·최소 설계 |
| 40~120분 | 필수 기능의 구현→방어→검증 반복 |
| 120~150분 | 누락 요구사항 검증·리뷰·중요 오류 수정 |
| 150~170분 | 필수 제출 문서·실행 재현·파일 점검 |
| 마지막 10분 | 저장·실제 제출 절차·완료 상태 확인 |

한 버그를 두 번 고치지 못하면 [90-debug](../prompts/90-debug.md)로 **최소 재현 → 경쟁 가설 → 판별 실험 → 최소 수정 → 같은 명령 재실행**을 요청합니다. 마감이 가까우면 [92-timebox](../prompts/92-timebox.md)로 P0 필수 기능·검증·제출 버퍼를 남기고 새 기능·전면 리팩터링을 중단합니다.

대화가 끊기거나 길어지면 [91-resume](../prompts/91-resume.md)을 사용합니다. 현재 파일·diff·실제 테스트에서 루트, 요구사항, 정책, 완료/미검증, 다음 작업 하나를 재구성합니다. 대화에서 이전에 "완료"라고 말한 것만으로 검증을 생략하지 않습니다.

## 6. 원본 스니펫과 템플릿의 정확한 사용 범위

기존 파일은 변경하지 않았습니다. 템플릿은 공식 제출 요구가 아니라 참고 양식이므로 **필수 파일명·경로·형식은 과제 안내를 따릅니다.**

```bash
bash /tmp/cofa-kit/help.sh dm
bash /tmp/cofa-kit/help.sh doc
bash /tmp/cofa-kit/help.sh qa
```

`data_audit.py`는 실제 CSV·JSON·JSONL 파일 경로 하나가 필요합니다. 아래 경로는 예시입니다.

```bash
python3 /tmp/cofa-kit/snippets/data_audit.py ~/workspace/data/data.csv
```

폴더를 자동 순회하지 않고 모든 행을 메모리에 읽으며 첫 행의 키를 기준으로 열을 조사합니다. SQLite·일반 로그·모든 중첩 JSON을 자동 지원하지 않습니다. 잘못된 JSONL 등에서는 실패할 수 있습니다. 일부 열의 `duplicates`는 반복값 수이지 업무상 중복 레코드 판정이 아닙니다. 음수나 극단값도 업무 기준을 확인한 뒤 해석합니다.

웹 과제에서는 다음 진단을 보조로 사용할 수 있습니다. 포트·경로는 실제 과제로 바꿉니다.

```bash
python3 /tmp/cofa-kit/snippets/smoke_test.py http://127.0.0.1:3000/api/health
```

CLI는 GET 하나의 상태·응답 일부·지연을 출력하고 실패를 종료 코드에 엄격히 반영하지 않습니다. 자동 검증에는 실제 본문·값·스키마·상태를 확인하는 별도 `assert`가 필요합니다. 서버가 `0.0.0.0`에 바인딩되어 있으면 같은 환경의 터미널은 `127.0.0.1`로 요청할 수 있습니다.

## 7. 설치 문제와 백업 복구

| 증상 | 대응 |
| :--- | :--- |
| `sk` 폴더가 이미 있음 | `git -C ~/sk remote -v`로 지정 저장소인지 확인하고 맞으면 `python3 ~/sk/scripts/install.py`를 실행합니다. 관련 없는 폴더는 삭제하지 않습니다. |
| 실제 과제 폴더가 없다는 오류 | 시험 화면과 `pwd`로 경로를 확인합니다. 빈 폴더를 만들어 과제라고 가정하지 않습니다. |
| 심볼릭 링크 경로 거절 | 설치 대상과 상위 경로를 확인하고 일반 폴더의 안전한 위치를 지정합니다. 링크를 자동 제거하지 않습니다. |
| `/tmp/cofa-kit`가 사라짐 | 임시 공간이 지워진 것일 수 있습니다. 클론 저장소에서 재설치하고 Codex 인식을 다시 확인합니다. |
| 설치 검사에서 파일 변경 감지 | 해당 파일이 의도적으로 바뀐 것인지 확인합니다. 과제 `AGENTS.md`를 수정했다면 그 차이도 검사 실패로 표시됩니다. |
| 설치 도중 실패 | 첫 오류·대상 경로·이미 복사된 파일·백업을 확인합니다. 설치는 전역 트랜잭션이 아니므로 부분 적용을 성공으로 간주하지 않습니다. |
| Codex 스킬이 안 보임 | 파일·설치 경로·제공 버전·재시작을 확인하고, 미지원이면 일반 프롬프트를 사용합니다. |
| 예전 전역 하네스와 충돌 | 이전 `~/.codex/AGENTS.md`는 자동 제거되지 않습니다. 원본 백업과 적용 규칙을 확인한 뒤 허용된 범위에서 직접 정리합니다. |

백업 위치는 설치 출력과 `/tmp/cofa-kit/installation.json`의 `backups`에 기록됩니다. 과제 파일에는 `workspace/AGENTS.md`, 스킬에는 `.agents/skills/...` 같은 상대 이름을 사용합니다.

복구는 **백업과 현재 파일을 먼저 비교한 뒤 필요한 파일 하나만** 되돌립니다. 백업 이후 새 변경이 있으면 덮어쓰기 전에 별도로 보존하세요. 다음 경로는 예시 자리표시자이므로 실제 설치 기록에서 확인한 값으로 바꿉니다.

```bash
diff -u "/실제/백업/AGENTS.md" "/실제/과제/AGENTS.md"
cp -- "/실제/백업/AGENTS.md" "/실제/과제/AGENTS.md"
```

전체 디렉토리를 삭제하거나 백업 전체를 무작정 덮어쓰지 않습니다. 다른 키트 위치를 사용했다면 `COFA_KIT_DIR` 또는 `--kit`을 일관되게 지정합니다. 백업을 장기 보존하려면 홈 아래 키트를 사용하세요.

## 8. 제출 준비와 사용 종료

10 단계는 **제출 준비**입니다. 필수 파일과 저장 상태, 실행 명령, 실제 테스트, 민감정보, 남은 문제를 확인하고 과제가 요구하는 문서를 실제 근거로 작성합니다. 외부 push·배포·제출 버튼은 프롬프트가 자동 처리하지 않습니다. 실제 제출은 시험 절차와 명시적 권한을 따르고 완료 화면까지 확인합니다.

11 단계는 과제 수행 중 허용되는 설명 연습·인수인계·회고입니다. 실제 설계·동작·검증을 짧게 말할 수 있는지 확인하세요. 후속 평가에서 AI·자료 참조·복사·붙여넣기가 금지되면 **프롬프트·스킬·요약 자료 사용을 중단**하고 실제 문항에 직접 답합니다. 준비용 주제를 공식 출제 문항이라고 단정하지 않습니다.

공개 준비 도구 저장소의 유지·공개 기간은 공식 안내를 확인합니다. 비공개 과제·데이터·자격증명·개인 시험 링크를 이 저장소에 올리지 마세요.
