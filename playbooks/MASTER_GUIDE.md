### [Step 2] 아키텍처 설계(Trade-off) 및 핵심 MVP 구현 (10:25 ~ 11:30)
한 번에 모든 기능을 다 짜라고 하면 버그가 섞입니다. **설계 근거(Why)를 먼저 밝히게 한 뒤 핵심 기능(Happy Path)부터 완성**시킵니다.

> **[Step 2-A 복붙 프롬프트: 아키텍처 설계 및 1단계 MVP 구현]**
> `$cofa-design` `@README.md` 요구사항과 업무 담당자에게 확인한 기준(`[확인한 답변 내용 입력]`)을 바탕으로 **1단계 핵심 기능(MVP)**을 구현해 줘.
> - **설계 근거 명시**: 코드를 수정하기 전에, 대안 A 대신 왜 현재의 구조 B를 선택했는지(장단점과 트레이드오프) 2줄로 먼저 설명해 줘.
> - **인터페이스 보존**: 기존에 작동하던 엔드포인트, 함수 시그니처, 필수 파일명은 그대로 유지해 줘.
> - **실행 확인**: 웹 서버나 UI가 있다면 내장 Browser에서 볼 수 있도록 반드시 호스트를 `0.0.0.0`에 바인딩해서 띄우고 실제 동작을 확인해 줘.

### [Step 3] 7대 예외사항 추론 & 엣지 케이스 방어 (11:30 ~ 12:05)
채점 시스템(메타 하네스)은 지원자가 제출한 코드에 **비정상 입력(Edge Case)**을 넣었을 때 죽는지 안 죽는지를 중점 채점합니다. 내가 일일이 생각하지 않아도 **`$cofa-edge` 스킬이 아래 7가지 표준 함정을 자동으로 추론해 방어 코드를 심어줍니다.**

| 번호 | 모든 실무 과제에 공통으로 숨어 있는 7대 엣지 케이스 체크리스트 | 방어 전략 (Guard Clause) |
| :--- | :--- | :--- |
| **① 결측치/빈 값** | `Null`, `None`, `NaN`, 빈 문자열(`""`), 빈 배열/객체(`[]`, `{}`) 유입 | 함수/API 최상단에서 체크 후 기본값 대체 또는 명시적 제외/400 응답 |
| **② 경계값/이상치** | `0`으로 나누기(ZeroDivision), 음수 온도/수량(`-999`), 임계치 경계(`>` vs `>=`) | 유효 범위(Min~Max) 필터링 및 `0` 분모 방어 |
| **③ 타입/스키마 오염** | 숫자 컬럼에 문자열(`"85.2"`, `"ERROR"`) 혼입, JSON 필수 키 누락 | `try-except` 파싱 방어 및 스키마 검증기 적용 |
| **④ 중복/멱등성** | 동일한 ID·타임스탬프 로그 중복 유입, 동일 API 요청 2회 연속 호출 | 고유 키(ID+Timestamp) 기준 중복 제거(Deduplication) |
| **⑤ 정렬/동점 처리** | 상위 N개 추출 시 점수가 같거나 시간이 같을 때 순서가 매번 바뀜 | 2차 정렬 키(예: `(-score, id_asc)`)를 명시해 결정론적(Deterministic) 결과 보장 |
| **⑥ 권한/상태 전이** | 허용되지 않은 상태 변경 요청, 존재하지 않는 리소스 ID 조회 | 500 서버 크래시 대신 정확한 400/403/404 상태 코드와 에러 메시지 반환 |
| **⑦ 서버 바인딩/경로** | `localhost` 바인딩으로 브라우저 접근 불가, 상대 경로 오류 | 호스트 `0.0.0.0` 바인딩 및 프로젝트 루트 기준 안전 경로 사용 |

> **[Step 3 복붙 프롬프트: 7대 엣지 케이스 전수 추론 및 방어 코드 주입]**
> `$cofa-edge` 현재 구현된 전체 코드를 7대 엣지 케이스 기준(①결측치/빈 입력, ②경계값/음수 이상치/0 나누기, ③타입/스키마 불일치, ④중복 데이터/멱등성, ⑤동점자 정렬 일관성, ⑥권한/잘못된 상태 요청 시 4xx 방어, ⑦`0.0.0.0` 바인딩)으로 전수 감사해 줘. 취약한 부분을 모두 찾아 방어 로직(Guard Clause)을 추가하고, 어디를 어떻게 방어했는지 표로 요약해 줘.

### [Step 4] 정상+예외 자동화 테스트 작성 및 Git 정합성 검증 (12:05 ~ 12:35)
