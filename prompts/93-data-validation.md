# 집계·이상탐지 데이터 검증

## 사용 시점

설비·센서·이벤트 로그·거래 데이터의 집계 결과나 이상탐지 결과를 제출 또는 리뷰하기 직전에 사용한다.

특히 행 수, 합계, 비율, 기간별 추세, 이상 건수, 모델 지표가 데이터 선택 규칙에 따라 달라지는 과제에 적용한다.

공식 안내와 과제 규칙이 있으면 그것을 먼저 읽고, AI 사용이 허용된 단계에서만 사용한다.

AI 금지 서술형 또는 평가가 시작되면 이 문서와 관련 스킬 사용을 중단한다.

## 필요 입력

- 실제 과제 루트: [과제 루트]
- 남은 시간: [남은 시간: 분]
- 요구사항·지표 정의·제출 형식: [요구사항/파일/답변]
- 원본 데이터와 스키마 또는 접근 방법: [파일/테이블/샘플]
- 집계·이상탐지 코드와 실행 명령: [코드/명령]
- 알려진 정답, 라벨 정의, 시간대 및 허용 오차: [정답/정책]

입력이 없으면 파일을 바꾸지 말고 실제 과제 루트와 데이터 위치, 집계 규칙, 이상 판정 기준만 질문한다.

샘플 몇 행만으로 전체 스키마나 결측 정책을 확정하지 않는다.

## 전략

먼저 산출물마다 단위를 고정한다. 한 행이 원시 관측인지, 장비-센서-시간창 집계인지, 이상 이벤트인지 명시한다.

집계의 포함·제외 조건을 표로 정리한다. 기간, 상태값, 장비 범위, 품질 플래그, 필수값, 중복 처리, 분모를 각각 기록한다.

모든 수치에 분모를 붙인다. 평균·비율·정확도는 분자, 분모, 0분모 정책, 반올림 시점이 없으면 검증 완료로 보지 않는다.

행 수는 원본 행, 필터 후 행, 유효 행, 그룹 수, 이상 행을 구분한다. 숫자가 달라도 어느 단계에서 달라졌는지 추적한다.

중복은 원본 완전 중복, 자연키 충돌, 동일 장비의 정상 반복 관측을 분리한다. 자연키가 불명확하면 임의로 제거하지 않는다.

결측은 제외, 0 대체, 보간, 오류 중 실제 코드와 요구사항이 선택한 정책만 적용한다. 결측을 0으로 바꾸면 분모와 합계에 미치는 영향을 별도 보고한다.

단위와 시간은 별도 위험 항목으로 검사한다. 단위 변환, UTC/현지시각, 시간창의 시작·끝 포함 여부, 이벤트 시간과 수집 시간을 비교한다.

독립 기대값은 제품 코드의 집계 경로를 재사용하지 않고 계산한다. 작은 고정 표본 수작업 계산과 별도 검증 스크립트/쿼리 중 가능한 방법을 사용한다.

이상탐지는 임계값, 기준 기간, 피처 생성 시점, 라벨 의미, 평가 분할을 확인한다. 실제 ML 과제일 때만 모델 지표를 다룬다.

학습/검증 분할에는 미래 정보, 같은 장비·같은 사건의 중복, 사후 확정 라벨, 전체 데이터로 계산한 정규화 통계가 새지 않는지 검사한다.

값이 좋아 보인다는 이유로 누수 의심을 무시하거나 지표·그래프·결측을 꾸미지 않는다.

원본 데이터와 기존 테스트는 수정·삭제하지 않는다. 검증에 필요한 새 테스트만 승인된 범위에서 만들고 실패를 숨기지 않는다.

## 기본 프롬프트

```text
$sk-data-validation
[과제 루트]에서 데이터 집계/이상탐지 결과를 읽기 중심으로 검증하라. 남은 시간은 [남은 시간: 분]이고, 요구사항은 [요구사항/파일/답변]이다.
공식 규칙과 AI 허용 범위를 먼저 확인하고, 후속 AI 금지 평가면 즉시 중단하라.
원본 데이터, 스키마, 호출 코드, 기존 테스트를 읽어 산출물별 관측 단위와 포함/제외 규칙을 정리하라.
원본 행→필터 후 행→유효 행→그룹 수→이상 행의 개수를 구분해 보고하라.
각 합계·평균·비율의 분자, 분모, 0분모/결측/반올림 정책을 코드와 요구사항 근거로 확인하라.
중복·결측·단위·시간대·시간창 경계를 점검하되, 근거 없이 행을 제거하거나 값을 보정하지 마라.
제품 집계 코드를 재사용하지 않는 독립 계산으로 핵심 합계와 행 수를 비교하라. 가능한 경우 작은 표본도 수작업 대조하라.
실행한 정확한 명령, 기대값, 실제값, 통과/실패와 검증 한계를 기록하라.
입력 또는 정책이 없으면 추측하지 말고 부족한 항목과 결과에 미치는 영향을 질문하라.
원본 데이터와 기존 테스트를 변경하지 말고, 수정이 필요하면 근거와 최소 수정 후보만 제시하라.
출력은 포함/제외 규칙, 독립 합계·행 수, 발견 사항, 재현 명령, 미검증/중단 사유 순서로 작성하라.
```

## 심화/반증 프롬프트

```text
$sk-data-validation
[과제 루트]의 이상탐지 또는 시계열 집계가 과도하게 좋아 보이거나 경계 시점에서 틀릴 가능성을 반증하라. 입력은 [요구사항/파일/답변]이며 남은 시간은 [남은 시간: 분]이다.
먼저 이상 한 건의 판정 단위, 임계값/기준선 산출 기간, 라벨 생성 시점, 이벤트 시간과 수집 시간을 명확히 하라.
다음 반례를 실제 데이터 또는 최소 합성 입력으로 각각 검사하라: 시간창 시작/끝 경계, 시간대 전환, 0·음수·결측 분모, 완전 중복과 자연키 충돌, 단위가 다른 센서, 빈 그룹, 늦게 도착한 이벤트.
ML이 실제로 있으면 시간 순서 분할, 장비/사건 단위 분리, 미래 피처, 전체 데이터 정규화, 사후 라벨 누수를 검사하라. ML이 없으면 이 검사는 해당 없음과 이유를 기록하라.
라벨이 있으면 이상/정상 건수와 혼동행렬의 각 분모를 독립 계산하고, 라벨이 없으면 정확도 같은 지표를 주장하지 마라.
제품 코드와 다른 간단한 계산 경로로 결과를 비교하고, 불일치마다 최초로 갈라지는 필터·그룹·시간창을 찾으라.
수정은 검증 실패가 요구사항 위반임이 확인되고 승인 범위에 있을 때만 최소로 제안하라. 원본 데이터 삭제, 행 임의 제거, 실패 테스트 삭제는 금지한다.
필수 정책이나 데이터가 없어 유효성 결론을 낼 수 없으면 통과 판정을 보류하고 정확한 질문과 안전한 다음 검증 하나를 제시하라.
출력은 반례별 입력·기대·실제·증거, 누수 판정, 지표 분모, 재현 명령, 잔여 위험으로 제한하라.
```

## 완료 기준

- 각 핵심 산출물의 관측 단위와 포함/제외 규칙이 근거와 함께 기록되어 있다.
- 핵심 합계·행 수·분모가 독립 계산으로 비교되었거나, 비교 불가 이유가 명시되어 있다.
- 결측·중복·단위·시간 경계와 해당 시 라벨·누수 검사가 실제 증거로 남아 있다.
- 정확한 실행 명령과 통과/실패, 미검증 항목이 구분되어 있다.
- 데이터나 정책이 부족하면 통과를 선언하지 않고 검증 보류와 질문으로 종료했다.

## 다음 단계

검증이 통과하면 `08-verify`에서 요구사항별 정상·경계·실패 테스트에 이 증거를 연결한다.

불일치가 재현되면 `90-debug`에서 경쟁 원인과 판별 실험을 세우고, 수정 권한이 있을 때만 최소 수정으로 진행한다.

필수 수치가 맞지만 제출 준비가 남았으면 `10-deliver`에서 파일·재현 명령·민감정보를 점검한다.

## 주의

집계 결과와 모델 지표는 데이터 선택 규칙이 없으면 해석하지 않는다.

공식 메일의 내용, 채점 방식, 모델 허용 여부, 정답 기준은 제공되지 않았으므로 만들어 내지 않는다.

"이상"은 업무 정의가 있어야 한다. 임계값이나 라벨의 의미가 없으면 탐지 성능을 단정하지 않는다.

검증은 실패를 발견하는 활동이다. 보기 좋은 값이나 제출 일정 때문에 불일치·누수·미검증을 숨기지 않는다.
