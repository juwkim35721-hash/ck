# 2.2 입출력·데이터 계약 (data_audit.py 사용)

> 스킬: `$sk-data-contract` · 단계: 구현 전 명세 정리·동결 · 작업 노트: `sk/work/SPEC.md#10. 입출력·데이터 계약` · 사용 자료: `sk/snippets/data_audit.py`

## 언제 쓰나

파일 데이터, API, 함수, CLI, UI 폼처럼 값이 경계를 넘는 과제에서 구현 전에 스키마와 오류 처리를 정리할 때 쓴다.
2.1에서 R/P/C/A를 정리한 다음 사용하고, 결과는 2.3이 T#를 만들 수 있을 만큼 구체적이어야 한다.
CSV·JSON·JSONL 파일이 있으면 감사 도구를 읽기 전용으로 실행해 이상 징후를 근거로 보강한다.

## 준비할 입력

- 대상: `<CSV·JSON·JSONL 파일 경로 또는 API·함수·화면 경계>`
- 관련 요구·정책: `sk/work/SPEC.md`, `sk/work/DM_LOG.md`
- 호출자·타입·테스트·샘플: `<경로 목록 또는 없음>`
- 민감정보 여부: `<있음/없음/불명>`
- 데이터 규모·접근 제한: `<파일 크기·행 수 추정 또는 불명>`
- 이미 관찰한 이상: `<결측·중복·음수·형식 오류 또는 없음>`

## 전략 — 왜 이렇게 하나

샘플 한 행은 가능한 값의 예일 뿐 전체 정책이 아니다.
계약은 입력, 정상 출력, 오류 출력을 분리하고 필드별 확정 상태와 근거를 붙여야 테스트가 구현을 독립적으로 판단할 수 있다.
감사 도구는 빠른 관찰용이다. 도구의 타입 판정·결측 판정·중앙값을 비즈니스 규칙으로 승격하지 않는다.
민감값은 출력하지 않고 개수·범위·익명화된 관찰만 남긴다.

## 기본 프롬프트

```text
$sk-data-contract
sk/work/SPEC.md와 sk/work/BRIEF.md를 먼저 읽고, <대상 파일 또는 API·함수·화면 경계>의 계약을 구현 전에 분석하라.
관련 호출자·타입·테스트·샘플은 <경로 목록 또는 없음>이고, 알려진 이상은 <결측·중복·음수·형식 오류 또는 없음>이다.
과제 코드·기존 테스트·원본 데이터는 수정하지 말고, SPEC의 10절만 갱신하라.

공식 문서, P#, 타입·호출자, 테스트, 샘플 순으로 근거를 모아 입력·정상 출력·오류 출력을 분리하라.
입력에는 필드, 타입, 필수성, 범위·형식, 결측 표현, 단위·시간대, 키·중복을 기록하라.
출력에는 필드, 변환, 정렬, 반올림, null·빈 결과를, 오류에는 조건·상태/예외·본문·부분 성공을 기록하라.
대상이 CSV/JSON/JSONL이면 python3 sk/snippets/data_audit.py <파일>을 읽기 전용으로 실행하고 행·열·결측·범위·중복 요약만 기록하라.
상위값·식별자 등 민감한 실제 값은 기록하지 마라.
도구는 CSV/JSON/JSONL만 지원하고 파일 전체를 메모리에 읽으며 숫자·결측 판정은 휴리스틱이라는 한계를 함께 적어라.
근거 없는 이상 처리 규칙은 만들지 말고 10절에 G 후보로 적어 2.1이 7절에 편입하게 하고, 1.3 질문 대상인지 판단하라.
마지막에 정상·경계·실패 테스트 입력 후보와 2.3에 넘길 계약 빈칸을 보고하라.
```

## 심화 프롬프트 — 파일 감사와 API 계약을 함께 반증할 때

```text
$sk-data-contract
<과제 문서 경로>, sk/work/SPEC.md, sk/work/BRIEF.md, sk/work/DM_LOG.md를 읽고,
파일 <데이터 파일 경로>와 API <메서드·경로 또는 없음>가 같은 데이터 의미를 유지하는지 읽기 전용으로 대조하라.
관련 타입·호출자·테스트·샘플은 <경로 목록>이다.

먼저 문서·P#·호출자·테스트·샘플에서 각 필드의 주장과 출처를 표로 모아라.
CSV/JSON/JSONL이면 python3 sk/snippets/data_audit.py <데이터 파일 경로>을 실행하고 종료 코드와 행·열·결측·범위·중복 요약을 기록하라.
파일 전체 메모리 적재, 숫자 50% 초과 파싱 휴리스틱, 고정 결측 토큰, 손상 JSONL 중단, TSV·Excel·Parquet 미지원 한계를 기록하라.
민감값·상위값·식별자는 그대로 출력하지 말고 개수 또는 익명화된 범위로 바꿔라.
입력 계약 표에는 필드·타입·필수·허용 형식·결측·단위·시간대·키·중복·근거 상태를 넣어라.
출력 계약 표에는 변환·정렬·반올림·null·빈 결과를, 오류 계약 표에는 조건·상태·본문·부분 성공·재시도를 넣어라.
API가 있으면 메서드·경로·요청·성공 상태/본문·오류 상태/본문·호환성 제약 표를 추가하라.
호출자와 타입 선언, 파일과 API, 문서와 P#가 다른 곳은 관찰 사실과 정책 미확정을 분리해 10절의 G 후보로 남기고 2.1에 인계하라.
관찰된 값만으로 빈 값·음수·중복 처리 방식을 확정하지 말고, 결과가 갈리는 작은 입력 예시와 필요한 DM 질문을 제시하라.
SPEC 10절만 갱신하고, 11절을 건드리지 않은 채 정상·경계·실패 T# 후보를 출력하라.
끝나면 확정/관찰됨이나 미확정/미확인 항목 수와 가장 위험한 계약 불일치를 보고하라.
```

## 변형 — 데이터 파일을 열 수 없거나 지원 형식이 아닐 때

```text
$sk-data-contract
대상 데이터 <파일 경로·형식>는 <접근 불가 사유 또는 TSV·Excel·Parquet 등 지원 불가 형식>이다.
sk/work/SPEC.md, 과제 문서, 타입 선언, 호출자, 제공 테스트, 안전하게 읽을 수 있는 샘플을 근거로 계약을 분석하라.
감사 도구를 성공한 것처럼 실행하거나 형식을 바꿔 원본을 저장하지 마라.
10절의 범위·근거에 미실행 사유와 검사 한계를 먼저 적어라.
확정 가능한 필수 키·타입·출력 스키마·오류 조건은 출처와 함께 쓰고, 데이터 분포·결측·중복·범위는 미확인으로 분리하라.
샘플 관찰을 전체 입력 허용 규칙으로 일반화하지 마라.
결과를 바꾸는 미확인 항목마다 G 후보의 영향·기본안·되돌릴 지점·DM 필요성을 10절에 적고 2.1에 인계하라.
2.3이 만들 수 있도록 정상·경계·실패 입력 후보를 제시하되, 근거 없는 수치 기대값은 쓰지 마라.
마지막에 파일 접근이 회복된 뒤 실행할 정확한 감사 명령과 확인 항목을 보고하라.
```

## 변형 — 오류 응답과 빈 결과가 핵심인 API 과제일 때

```text
$sk-data-contract
<API 메서드·경로 목록>의 입출력·오류 계약을 sk/work/SPEC.md 10절에 정리하라.
과제 문서, 라우트 코드, 호출자, 타입 선언, 제공 테스트, sk/work/DM_LOG.md를 읽기 전용으로 대조하라.
성공 사례뿐 아니라 누락 필드, 잘못된 타입, 존재하지 않는 리소스, 빈 결과, 중복 요청의 계약 근거를 찾아라.
각 경로에 메서드·경로·파라미터/본문·성공 상태·성공 스키마·오류 상태·오류 본문·부분 성공·재시도를 표로 기록하라.
서버를 임의로 띄우거나 포트·호스트를 바꾸지 말고, 실제 실행 근거가 없으면 관찰됨이나 미확정으로 표시하라.
상태 코드나 오류 메시지가 문서·테스트에 없으면 관례로 만들지 말고 10절의 G 후보로 남겨 2.1에 인계하라.
정렬·반올림·null 표현·빈 배열/404의 구분처럼 결과가 갈리는 부분은 작은 요청 예시와 함께 DM 질문 후보로 제시하라.
정상·경계·실패 T# 후보를 남기고 11절은 수정하지 마라.
끝나면 2.3에서 우선 변환할 계약과 BLOCKED 위험을 보고하라.
```

## 결과물 확인

- `sk/work/SPEC.md`의 10절에 범위·근거, 입력, 키·시간, 출력, 오류, 해당 API 계약이 분리됐는가?
- 각 필드·규칙이 확정/관찰됨이나 미확정/미확인 중 하나와 출처를 가졌는가?
- 감사는 정확한 명령으로 실행했거나, 미실행 사유·형식·메모리·휴리스틱 한계를 적었는가?
- 이상 징후를 정책으로 단정하지 않고 필요한 G 후보·2.1 인계·DM 연결을 남겼는가?
- 2.3이 쓸 정상·경계·실패 입력 후보가 있는가?

## 주의

`data_audit.py`는 CSV·JSON·JSONL만 대상으로 하며 파일 전체를 메모리에 읽는다. 큰 파일이나 지원 밖 형식은 무리하게 변환하지 않는다.
손상 JSONL, 민감정보, 고정 결측 토큰, 숫자 판정 휴리스틱의 한계를 숨기지 않는다.
원본 데이터·코드·기존 테스트를 수정하거나 서버를 임의로 실행·배포·제출하지 않는다.
실행하지 않은 감사·API 결과를 통과 또는 확정으로 쓰지 않는다.
