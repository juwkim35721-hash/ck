# 맥락 복구·작업 인수인계
## 사용 시점
대화가 끊겼거나 담당자가 바뀌어 현재 과제의 실제 상태를 짧게 다시 잡아야 할 때 사용한다.

작업 재개 직전, 오류 보고를 받은 직후, 또는 제출 준비 전에 특히 적합하다.

이 단계의 목적은 새 구현 계획을 만드는 것이 아니라 현재 증거로 상태를 복원하고 다음 한 작업을 정하는 것이다.

공식 안내와 현재 과제의 규칙이 이 문서보다 항상 우선한다.

후속 평가가 AI 사용 금지라면 즉시 이 프롬프트와 모든 AI 보조 사용을 중단한다.

## 필요 입력
- [과제 루트]: 준비 도구 저장소가 아닌 실제 과제 디렉터리
- [남은 시간: 분]: 모르면 `미확인`으로 둔다
- [요구사항/파일/답변]: 공식 요구사항, 담당자 답변, 오류 보고 중 있는 것만 제공한다
- [직전 작업 주장]: 있으면 참고만 하고 사실로 확정하지 않는다
- [허용된 실행 범위]: 읽기·테스트·수정·외부 동작의 허용 여부

공식 안내 메일이나 담당자 답변이 없다면 그 빈칸을 추정으로 채우지 않는다.

자격증명, 토큰, 개인정보, 원본 민감 데이터는 입력과 결과에서 값 자체를 인용하지 않는다.

## 전략

먼저 [과제 루트]가 실제 과제인지 확인하고, 준비 도구 저장소를 과제로 오인하지 않는다.

대화의 "완료" 주장은 가설로 취급하고 현재 파일, `git status`, `git diff`, 요구사항 원문, 실제 실행 결과로 다시 확인한다.

증거는 다음 세 칸으로 분리한다: 파일·명령 결과로 확인한 **사실**, 사람이 말했으나 재확인하지 못한 **주장**, 자료가 없어 판단할 수 없는 **미확인**.

요구사항 ID나 수용 기준이 있으면 각 항목을 완료·진행 중·미검증·불명으로 표시한다. 없으면 새 ID를 발명하지 않는다.

기존 실행 스크립트, 문서화된 명령, CI 설정에서 검증 명령을 찾는다. 그럴듯한 테스트 명령을 새로 만들어 성공처럼 보고하지 않는다.

마지막 검증은 실제로 실행했는지, 실행 명령·시각·결과가 남아 있는지 구분한다. 오래된 결과는 현재 diff 이후의 증거가 아니라고 표시한다.

실행이 허용되면 가장 관련성 높은 기존 검증 하나만 재실행한다. 실패하면 실패 출력의 핵심과 재현 명령을 남기고 원인 추측이나 반복 실행을 멈춘다.

읽기 전용 단계로 끝내며 파일 수정, 테스트 삭제, 의존성 변경, 제출·push·배포를 하지 않는다. 수정이 필요하면 다음 작업 후보로만 적는다.

다음 작업은 가장 높은 위험 또는 막힌 필수 요구사항을 줄이는, 5~30분 안에 끝나는 원자 작업 하나로 제한한다.

## 기본 프롬프트

```text
$sk-resume
실제 과제 상태를 읽기 전용으로 복구하라. [과제 루트]는 [과제 루트], 남은 시간은 [남은 시간: 분], 사용 가능한 자료는 [요구사항/파일/답변]이다.

1. 공식 규칙에 AI 사용 금지가 있으면 즉시 중단 사실만 알리고 진행하지 마라.
2. 과제 루트와 적용 규칙을 확인하고, 현재 파일·git status·git diff·요구사항 원문·기존 테스트 설정을 읽어라. 대화의 완료 주장은 증거로 재확인하라.
3. 요구사항별 상태와 변경 상태를 사실/주장/미확인으로 분리하라. 비밀값·개인정보·민감 원문은 인용하지 마라.
4. 현재 diff 이후에도 유효한 마지막 검증 명령과 결과를 찾아라. 실행이 허용되고 기존 명령이 명확하면 가장 관련된 검증 하나만 실행하라. 명령이 불명확하거나 실패하면 그 사실을 남기고 멈춰라.
5. 파일을 수정하거나 외부 동작을 하지 말고, 가장 위험한 미확인 하나를 줄일 다음 원자 작업 하나만 제시하라.

아래 형식으로 12줄 이내 상태 캡슐을 작성하라.
- 과제 루트/규칙:
- 완료 또는 확인된 사실:
- 진행 중 또는 변경 상태:
- 주장(미재확인):
- 미확인·차단 요인:
- 마지막 검증: [명령 | 실행 여부 | 결과 | 현재 diff와의 관계]
- 다음 한 작업: [목적 | 예상 5~30분 | 완료 판정]
- 중단 조건:
```

## 심화/반증 프롬프트

```text
$sk-resume
[과제 루트]의 인수인계 요약이 틀렸다는 가정으로, 수정 없이 반증 점검을 수행하라. 참고 자료는 [요구사항/파일/답변]이고, 남은 시간은 [남은 시간: 분]이다.

우선 실제 루트와 공식 규칙을 확인한다. AI 사용 금지 단계면 더 이상 진행하지 않는다. 그 다음 현재 diff, 호출 지점, 요구사항, 기존 검증 설정을 대조하여 다음을 찾는다: (a) 완료라고 했지만 diff나 호출자에 없는 기능, (b) 변경됐지만 요구사항과 연결되지 않는 파일, (c) 현재 변경보다 오래된 테스트 결과, (d) 실행 불가·누락된 검증, (e) 민감정보 노출 위험.

사실에는 파일 경로·명령·출력 요약처럼 확인 가능한 근거만 붙이고, 추측은 `주장` 또는 `미확인`으로 표시한다. 새 테스트, 수정, 삭제, 제출, push, 배포는 하지 마라. 기존의 안전한 검증 명령 하나가 분명하고 실행이 허용될 때만 실행하라.

결과는 다음 여섯 항목만 작성하라.
1. 반증 결과: 확인됨/불일치/판단 불가
2. 가장 중요한 근거 최대 3개
3. 요구사항 상태: 완료·진행 중·미검증·불명
4. 마지막 검증의 신뢰도와 한계
5. 즉시 중단할 조건
6. 다음 한 작업과 완료 판정
```

## 완료 기준

실제 과제 루트와 적용 규칙이 명시되어 있다.

완료 주장과 확인된 사실, 미확인 항목이 섞이지 않고 구분되어 있다.

마지막 검증에 실제 명령·실행 여부·결과·한계가 함께 있다. 실행하지 못했으면 그 이유가 명확하다.

민감정보를 복사하지 않았고, 다음 작업이 정확히 하나이며 수정·외부 동작을 약속하지 않는다.

## 주의

없던 공식 메일, 정책, 테스트 통과, 제출 상태를 만들어 쓰지 않는다.

`git diff`가 비어 있어도 완료를 뜻하지 않으며, diff가 있어도 요구사항 충족을 뜻하지 않는다.

사용자와 무관한 기존 변경은 보존하고, 정리 명목의 reset·삭제·전면 재작성은 하지 않는다.

외부 제출·배포·push는 사용자의 별도 구체적 승인 없이는 절대 실행하지 않는다.
