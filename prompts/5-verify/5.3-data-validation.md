# 5.3 데이터 정합성 독립 검산 (data_audit.py 사용)

> 스킬: `$sk-data-validation` · 단계: 검증·증거 · 작업 노트: `sk/work/EVIDENCE.md#실행 기록`, `sk/work/SPEC.md#12. 추적표` · 사용 자료: `sk/snippets/data_audit.py`

## 언제 쓰나

CSV, JSON, JSONL 원본을 읽어 결과 파일·집계·순위를 만드는 기능을 구현한 뒤 쓴다.
필터·제외·중복 제거·반올림·그룹 합계가 정확한지, 구현과 다른 방법으로 수치를 다시 계산해야 할 때 쓴다.
원본 파일이 없거나 화면/API 동작만 검증할 때는 이 프롬프트 대신 API·UI 검증을 쓴다.
이 프롬프트는 데이터를 고치거나 누락 행을 복구하는 작업이 아니다.

## 준비할 입력

- `sk/work/SPEC.md`의 `## 5. 확정 정책 P`, `## 10. 입출력·데이터 계약`, T#.
- 원본 데이터, 결과 데이터, 제외 목록·오류 로그의 실제 상대 경로.
- 구현이 사용하는 집계 방법과 다른 독립 계산 수단.
- `sk/work/EVIDENCE.md`의 최신 E# 및 현재 코드 상태.
- 민감 정보 없이 비교할 수 있는 키·행 수·그룹·합계 기준.

## 전략 — 왜 이렇게 하나

같은 코드·쿼리·함수를 다시 실행해 일치했다고 해도 독립 검증이 아니다.
감사 스니펫으로 구조·결측·범위를 먼저 비교하고, 표준 라이브러리나 별도 최소 계산으로 행 수·합계·그룹 수를 다시 계산한다.
1:1 처리라면 입력 행 = 결과 행 + 사유별 제외 행을 대사하고, 집계·조인이라면 키·그룹·단계별 개수로 바꾼다.
스니펫의 형식·메모리·숫자 휴리스틱 한계를 밝히면 도구의 출력만 과신하지 않게 된다.

## 기본 프롬프트

```text
$sk-data-validation
원본과 결과 데이터의 정합성을 독립 검산해줘.
먼저 sk/work/SPEC.md의 5절 P, 10절 데이터 계약, 관련 T#를 읽고 원본·결과·제외 목록 경로를 확인해줘.
각 파일에 아래 명령을 실제로 실행해 행 수, 컬럼, 결측, 범위, 중복을 비교해줘.
python3 sk/snippets/data_audit.py <원본_파일>
python3 sk/snippets/data_audit.py <결과_파일>
CSV/JSON/JSONL만 지원하고 전체 파일을 메모리에 읽으며 숫자 판정이 휴리스틱이라는 한계를 결과에 밝혀줘.
구현과 다른 방법으로 행 수, 핵심 합계 또는 그룹별 개수 중 요구사항에 맞는 수치를 다시 계산해줘.
1:1 변환이면 입력 행 = 결과 행 + 사유별 제외 행을, 집계면 키·그룹·단계별 수를 대사해줘.
P#의 결측·중복·범위 제외, 단위·반올림, 정렬·동점 규칙이 실제 결과에 반영됐는지 확인해줘.
원본 데이터·결과 파일·과제 코드는 수정하지 말고, 실제 실행 결과를 E#로 기록해줘.
일치·불일치는 PASS, FAIL, 미검증으로만 판정하고 불일치는 재현 자료와 함께 6.1 debug으로 넘겨줘.
끝에 감사 비교, 독립 계산식·수치, 정책 확인, E#, 다음 행동을 보고해줘.
```

## 심화 프롬프트 — 제외 사유와 반올림까지 대사하는 상황

```text
$sk-data-validation
데이터 결과가 제출 산출물이므로 정책별 처리 결과까지 엄격히 독립 검산해줘.
SPEC.md의 R#, P#, AC, 10절 입력·출력 계약, 11절 T를 읽고 각 정책이 어느 파일·열·집계에 영향을 주는지 정리해줘.
원본·중간 산출물·최종 결과가 있으면 각각 경로와 생성 순서를 확인하고, 생성이 끝난 파일만 읽어줘.
원본과 최종 결과에 data_audit.py를 실행해 행 수·컬럼·결측·숫자 범위·중복을 비교해줘.
JSONL 손상 줄, TSV·Excel·Parquet, 대용량 메모리 문제에는 스니펫 결과를 억지로 해석하지 말고 대체 방법과 미검증 범위를 밝혀줘.
구현이 pandas면 csv/json 표준 라이브러리, 구현이 SQL이면 내보낸 결과의 표준 라이브러리 계산처럼 다른 경로를 선택해줘.
유효·제외 기준을 P#로 명시한 뒤 결측, 중복, 범위 오류 등 제외 사유별 건수를 독립적으로 세어줘.
1:1인 단계는 입력 행 = 출력 행 + 제외 행, 집계인 단계는 유니크 키·그룹 수·총합을 대사해줘.
총합·평균·그룹별 개수·순위 중 AC가 요구하는 값은 별도 계산하고, 반올림 시점과 단위 변환 시점을 P#와 대조해줘.
열 이름, null 표현, 빈 결과, 정렬, 동점 순서도 10절 계약과 실제 결과를 비교해줘.
민감 식별자·개별 원본 값은 기록하지 말고 마스킹된 키·행 번호·집계만 써줘.
각 실제 명령과 핵심 수치를 EVIDENCE의 E#로 남기고 SPEC 12절에는 실제 E#만 연결해줘.
불일치의 최초 단계·차이 수·영향 P#만 좁히고 코드·데이터는 수정하지 말고 6.1 debug으로 인계해줘.
끝에 대사 식, 사유별 제외 수, 독립 계산 근거, PASS/FAIL/미검증, E#를 표로 보고해줘.
```

## 변형 — 지원하지 않는 데이터 형식 또는 대용량 파일

```text
$sk-data-validation
데이터가 TSV·Excel·Parquet이거나 커서 data_audit.py를 그대로 쓰기 어려워. 정합성을 안전하게 검증해줘.
먼저 파일 형식·크기·민감도와 SPEC 10절의 계약을 확인하고, 스니펫이 CSV/JSON/JSONL만 지원하며 전체 파일을 메모리에 읽는 한계를 명시해줘.
지원하지 않는 형식에 스니펫을 억지로 실행해 통과로 해석하지 말고, 이미 프로젝트에 있는 읽기 도구 또는 표준 라이브러리 스트리밍으로 행 수·필수 열·핵심 집계만 독립 계산해줘.
구현 코드와 같은 함수·쿼리·변환 모듈 재호출은 금지하고 다른 경로를 선택해줘.
가능한 범위에서 입력·출력 행/키/그룹·사유별 제외 수와 핵심 합계를 대사하고, 확인하지 못한 범위는 미검증으로 적어줘.
실제 명령·결과·한계를 E#로 남기고 원본·결과·과제 코드는 수정하지 마.
불일치가 있으면 최초 차이 단계와 E#를 6.1 debug으로 넘겨줘.
```

## 변형 — 시간이 10분 이하인 상황

```text
$sk-data-validation
시간이 매우 부족하니 P0 데이터 처리의 최소 독립 검산만 해줘.
원본·결과 파일 경로와 P0 P#를 확인한 뒤 data_audit.py를 두 파일에 각각 한 번 실행해줘.
전체 행 수, 핵심 합계 하나, P0 제외 수, 결과 정렬·동점 하나를 구현과 다른 방법으로 대사해줘.
1:1이면 입력 행 = 결과 행 + 제외 행을 확인하고, 집계면 유니크 키·그룹 수·총합을 확인해줘.
나머지 필드·P1/P2·대용량 전체 검증은 미검증으로 명시하고 PASS로 넓히지 마.
실제 결과·코드 상태를 E#로 남기고 불일치는 6.1 debug으로 넘겨줘. 데이터와 코드는 수정하지 마.
```

## 결과물 확인

- 원본과 결과 각각에 감사 명령 또는 형식에 맞는 대체 점검을 실제로 실행했다.
- 구현과 다른 방식으로 행 수·키/그룹·핵심 합계를 계산했다.
- P#의 제외 사유, 반올림·단위, 정렬·동점 중 적용 항목을 확인했다.
- 스니펫의 CSV/JSON/JSONL, 메모리, 휴리스틱 한계가 기록되어 있다.
- E#에는 실제 명령·대사 수치·판정·코드 상태가 있다.

## 주의

원본 데이터와 결과 파일을 고쳐 숫자·행 수를 맞추지 않는다.
같은 집계 함수·쿼리 결과를 다시 읽어 독립 검산이라고 하지 않는다.
민감 식별자, 상위값, 원본 행, 개인정보를 채팅·EVIDENCE에 복사하지 않는다.
손상 JSONL·지원하지 않는 형식·메모리 실패를 통과로 해석하지 않는다.
새 패키지 설치, 외부 전송, 코드 수정은 이 검증 프롬프트의 범위 밖이다.
