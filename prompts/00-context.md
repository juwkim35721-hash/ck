# 환경·규칙·기준선 확인

## 사용 시점

과제를 받았거나 작업을 재개한 직후, 코드·설정·데이터를 바꾸기 전에 사용한다.
준비 도구 저장소 `~/sk`와 실제 과제 루트를 구분해야 할 때 사용한다.
요구사항이나 공식 안내가 일부만 제공되었으면 추정 대신 확인 범위를 정하는 데 사용한다.

## 필요 입력

- [과제 루트]: 실제 과제라고 알려진 절대 경로. 모르면 `미확인`으로 둔다.
- [남은 시간: 분]: 현재 남은 시간. 모르면 `미확인`으로 둔다.
- [요구사항/파일/답변]: 제공된 과제 설명, 공식 안내, 사용자 지시, 저장소 상태.
- [허용된 명령 또는 도구]: 이미 허용·설치되었다고 확인된 정보.

대괄호 입력은 실행 전에 실제 정보로 바꾼다.
공식 안내 메일이나 답변이 제공되지 않았다면 그 내용을 추정하거나 만들어 내지 않는다.

## 전략

1. 현재 위치, 실제 과제 후보, Git 최상위 경로를 읽기 전용으로 확인한다.
2. `~/sk`는 준비 도구임을 전제로 하고, 명시적 근거 없이는 과제 루트로 채택하지 않는다.
3. 사용자 지시, 과제 문서, 적용 범위의 지침 파일을 출처와 함께 분리해 읽는다.
4. AI 사용 가능 여부와 제출·외부 동작 제한은 제공된 공식 안내를 최우선으로 기록한다.
5. 언어·패키지·테스트 설정을 찾아 기존 기준선 명령 후보만 고른다.
6. 설치, 의존성 변경, 다운로드, 빌드 산출물 생성 가능성이 있는 명령은 실행하지 않고 이유를 남긴다.
7. 안전하다고 확인된 기존 검사만 정확한 명령과 종료 상태로 기록한다.
8. 자격증명·토큰·개인정보가 의심되는 파일은 값을 열거나 출력하지 않고 경로·유형만 위험으로 표시한다.
9. 루트·규칙·안전한 기준선 중 하나라도 불명확하면 코드 변경 없이 질문 또는 중단한다.

이 단계의 산출물은 환경·제약 요약과 기준선 증거이며 구현 계획이나 수정안이 아니다.
판단 근거와 실제 실행 증거만 짧게 보고하고, 전체 사고 과정을 요구하거나 기록하지 않는다.

## 기본 프롬프트

```text
$sk-context
당신은 00-context 단계만 수행한다. 코드를 포함한 어떤 파일도 수정하지 말고,
외부 제출·배포·push·로그인·비밀정보 업로드를 하지 마라.

입력:
- 실제 과제 루트 후보: [과제 루트]
- 남은 시간: [남은 시간: 분]
- 제공된 요구사항/공식 안내/답변: [요구사항/파일/답변]
- 허용된 명령 또는 도구: [허용된 명령 또는 도구]

다음 순서로 읽기 전용 점검을 수행하라.
1) 현재 작업 위치와 Git 최상위 경로를 확인하고, 준비 도구 ~/sk와 실제 과제 루트를 구분하라.
2) 적용되는 사용자 지시·과제 문서·지침 파일을 출처별로 요약하라. 제공되지 않은 공식 규칙은 미확인으로 남겨라.
3) 프로젝트의 언어, 패키지 관리자, 기존 테스트·실행 명령 후보를 파일 근거와 함께 찾으라.
4) 설치·다운로드·생성·변경 없이 안전함이 확인되는 기존 검사만 실행하라. 실행하지 못하면 정확한 이유를 써라.
5) 비밀정보 위험은 값 없이 경로 또는 유형으로만 보고하라.

아래 형식으로만 답하라.
- 실제 과제 루트: [근거/미확인]
- 적용 규칙과 금지: [출처별 요약/미확인]
- 도구 가용성: [확인한 도구와 근거]
- 기준선: [정확한 명령, 종료 상태, 핵심 결과] 또는 [미실행 사유]
- 수정 금지 범위: [현재 단계의 경계]
- 비밀정보 위험: [없음/값 없는 경로·유형]
- 다음 확인 항목: [최대 3개]
- 진행 게이트: [다음 단계 가능/질문 필요/중단]
```

## 심화/반증 프롬프트

```text
$sk-context
00-context 결과를 반증 중심으로 재점검하라. 파일을 수정하거나 새 명령을
추측해 실행하지 말고, 이미 확인한 사실과 각 근거만 사용하라.

다음을 확인하라.
- 실제 과제 루트라고 한 경로가 ~/sk 또는 다른 준비·상위 저장소와 혼동되지 않는가?
- 적용 규칙이 사용자 지시, 과제 문서, 지침 파일 중 어느 출처에 근거하는가?
- 기준선 명령이 프로젝트 설정에 실제로 존재하며 설치·다운로드·생성 위험이 없는가?
- 성공처럼 보이는 출력만 기록하고 종료 상태, 실패, 미실행 사유를 누락하지 않았는가?
- 로그·환경 변수·설정 파일에서 비밀값을 노출했거나 노출할 가능성이 없는가?

반례가 있으면 '진행 불가'로 표시하고 최소 질문 하나만 제시하라.
반례가 없으면 아래 형식으로 답하라.
- 확인된 사실: [사실 — 근거]
- 취소된 가정: [없음 또는 가정 — 이유]
- 기준선 신뢰도: [높음/제한적/미확인 — 이유]
- 중단 또는 질문 조건: [구체 조건]
- 다음 단계에 넘길 사실: [짧은 목록]
```

## 완료 기준

실제 과제 루트가 근거와 함께 확인되었거나, 확인 불가라는 사실과 질문이 명확하다.
적용 규칙과 AI·외부 동작 제약이 출처별로 기록되었고, 미제공 정보는 미확인으로 남는다.
기준선은 정확한 명령·결과로 남기거나, 미실행 원인과 안전한 다음 확인 방법이 남는다.
비밀값 없이 위험 위치만 분류했고 어떤 파일도 변경하지 않았다.

## 다음 단계

진행 게이트가 통과하면 01-define에서 요구사항과 완료 기준을 분해한다.

## 주의

공식 안내 메일은 주어지지 않았으므로 모델명, 시험 일정, AI 금지 범위, 채점 방식, 출제 문항을 주장하지 않는다.
공식 규칙이 AI 사용을 금지하거나 후속 AI 금지 서술형이 시작되면 이 문서·스킬·암기자료 사용을 즉시 중단한다.
실패한 검사, 실행 불가, 비어 있는 결과를 성공으로 바꾸어 보고하지 않는다.
