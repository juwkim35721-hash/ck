# 9.3 설명 연습·꼬리질문 대비

> 스킬: `$sk-qa-drill` · 단계: 후속 서술형 6문항 대비 · 작업 노트: `sk/work/QA_CARD.md#연습 기록` · 사용 자료: 없음

## 언제 쓰나

제출 전 AI 사용이 허용되는 동안, 6문항 카드가 준비된 뒤 한 문항씩 카드를 보지 않고 말해 보는 단계다. 사용자 스스로 답한 뒤에만 코드·노트 근거로 사실 오류와 빠진 요소를 대조한다.

AI·복붙 금지 단계가 시작된 뒤에는 질문을 제시하거나 답안을 교정하거나 카드를 열람하지 않는다. 이 프롬프트는 모범 답안을 받아 적는 기능이 아니라 내가 만든 구현을 내 말로 설명하는 훈련이다.

## 준비할 입력

- AI 사용이 허용된다는 확인 및 문항당 5분 이상 남은 시간
- `sk/work/QA_CARD.md`의 해당 Q 절. 연습 시작 시에는 사용자에게 보여 주지 않는다.
- 대조 근거인 `sk/work/UNDERSTANDING.md`, `SPEC.md`, `DECISIONS.md`, `EVIDENCE.md`
- 연습할 문항 번호 하나(Q1~Q6)
- 민감값을 생략한 설명. 실제 비밀값·개인정보는 입력하지 않는다.

## 전략 — 왜 이렇게 하나

카드를 보며 읽으면 실제 서술형에서 막힐 수 있다. 먼저 무참조로 답하면 선택 이유, 코드 위치, 정책, 검증, 한계 중 빠진 축을 정확히 발견할 수 있다. 이후 피드백은 완성 답안을 대신 쓰지 않고 “어떤 사실을, 어느 근거에서, 왜 포함해야 하는지”만 제공해야 사용자의 이해가 남는다.

한 번에 한 문항, 5분 제한을 두면 문항별 약점이 분리된다. 연습 기록은 답변 전문이 아니라 맞춘 근거·오류·누락·다음 행동만 남겨 이후 보완을 빠르게 한다.

## 기본 프롬프트

```text
$sk-qa-drill
지금은 제출 전이며 AI 사용이 허용된 시간이다. Q<번호> 하나만 5분 제한으로 연습하자.
먼저 카드를 보지 말고 내 구현을 내 말로 답하도록 요청하라. 내가 답하기 전에는 힌트·파일명·모범 답안을 주지 마라.

답을 받으면 `sk/work/QA_CARD.md`, `sk/work/UNDERSTANDING.md`, `SPEC.md`, `DECISIONS.md`, `EVIDENCE.md`와 대조하라.
맞춘 사실, 사실 오류 또는 확인 필요, 빠진 Why/How/Edge/Verification/Business/Limit 축을 표로 돌려줘라.
완성 답안을 대필하지 말고 내가 다시 쓸 때 넣어야 할 사실과 근거 위치만 2~4개 제시하라.

실제 카드 약점에 연결된 꼬리질문 하나를 낸 뒤 내 재답을 받는다.
`sk/work/QA_CARD.md`의 `## 연습 기록`에 새 연습 회차를 표 형식으로 추가하라.
코드·테스트·카드 본문은 수정하지 말고, AI 금지 단계가 시작되면 즉시 중단하라.
```

## 심화 프롬프트 — 여러 축을 혼동하거나 사실 오류가 반복되는 상황

```text
$sk-qa-drill
AI 사용이 허용된 제출 전 연습이다. 먼저 Q<번호> 한 문항만 카드를 보지 않고 5분 안에 답하게 해라.
사용자가 답하기 전에는 `QA_CARD.md` 내용, 파일명, ID, 정답 문장을 공개하지 마라.

답변 뒤에는 다음 원천과만 비교하라: `sk/work/QA_CARD.md`, `UNDERSTANDING.md`, `SPEC.md`, `DECISIONS.md`, `EVIDENCE.md`.
대조표 열은 `항목 | 사용자가 맞힌 사실 | 원천과 다른 주장 | 누락 축 | 확인할 근거 위치`로 하라.
사실 오류는 '사용자 주장 → 원천 사실 → 재확인할 위치' 순서로 짧게 설명하고, 원천이 없으면 확인 필요로 남겨라.

답안을 완성해 주지 말고, 재답에 포함할 사실 세 개와 스스로 답할 질문 두 개만 제공하라.
꼬리질문은 다음 중 실제 약점 하나로 골라라: 대안을 택하지 않은 이유, 이 테스트가 놓친 것, 정책이 바뀌면 영향받는 코드.
재답을 받은 뒤 첫 답과 달라진 점과 남은 약점만 정리하라.

`sk/work/QA_CARD.md`의 `## 연습 기록`에 새 연습 회차를 추가하고, 같은 오류가 두 회차 연속이면
`9.1 understand ($sk-understand)` 또는 `9.2 qa-card ($sk-qa-card)` 중 필요한 곳으로 인계하라.
과제 파일·Q1~Q6 카드 본문·제출물은 수정하지 마라.
```

## 변형 — Q4 검증 및 AI 교정 문항 연습

```text
$sk-qa-drill
AI 사용 허용 시간에 Q4만 5분 무참조 연습하자. 답하기 전에는 카드·정답·테스트 이름을 보여 주지 마라.
내 답을 받은 뒤 정상·경계·실패 검증이 T#/E#와 맞는지, 최신 코드 기준인지, PASS/FAIL/미검증이 구분되는지 확인하라.
AI 교정은 실제 AI#가 있을 때만 말했는지도 확인하라.

완성 답안을 주지 말고, 빠진 검증 범위·증거 ID·AI 주장 오류만 표로 알려줘라.
이어 '이 테스트가 놓치는 것은 무엇인가?'라는 꼬리질문 하나를 내고 재답을 받으라.
`sk/work/QA_CARD.md`의 `## 연습 기록`에 연습 회차를 추가하되, 답변 전문과 민감값은 저장하지 마라.
```

## 변형 — Q6 한계 설명이 일반론인 상황

```text
$sk-qa-drill
AI 사용 허용 시간에 Q6 한 문항을 카드 없이 5분 안에 답하게 해라.
답변 뒤 `sk/work/UNDERSTANDING.md`의 `## 한계·실패 조건·개선안`과 실제 코드 근거를 대조하라.
현재 선택, 구체 실패 조건, 바꿀 파일·함수/계약, 검증 방법이 각각 있는지 확인하라.

'확장성 부족'처럼 일반적인 표현은 어떤 실제 구조에서 왜 발생하는지 재질문하라.
무관한 기술을 제안하거나 모범 3문장을 쓰지 말고, 사용자가 다시 답할 수 있는 사실 기반 질문만 제공하라.
연습 결과는 `sk/work/QA_CARD.md`의 `## 연습 기록`에 추가하고 필요하면 `9.4 retrospect ($sk-retrospect)`로 넘겨라.
```

## 결과물 확인

- 사용자가 카드 없이 한 문항을 먼저 답했고, AI가 선행 답안을 주지 않았다.
- 피드백 표가 맞춘 사실·오류/확인 필요·누락 축·근거 위치를 구분한다.
- 피드백은 근거가 있는 사실만 말하며 복붙 가능한 완성 답안이 아니다.
- 꼬리질문은 카드의 실제 약점과 연결되고, 재답 기회가 제공됐다.
- `QA_CARD.md`의 `## 연습 기록`에 새 연습 회차가 추가됐고 Q1~Q6 카드 본문은 보존됐다.

## 다음 단계

반복 오류가 코드 흐름 이해 부족이면 [9.1 이해 지도](../9-qa/9.1-understand.md)의 `$sk-understand`로, 카드 근거·문장 구조 부족이면 [9.2 QA 카드](../9-qa/9.2-qa-card.md)의 `$sk-qa-card`로 돌아간다. 실제 결함 가능성이면 `6.1 debug ($sk-debug)`으로 인계하고, 근거 없는 한계 설명은 [9.4 한계 정리](../9-qa/9.4-retrospect.md)의 `$sk-retrospect`로 정리한다.

## 주의

AI·복붙 금지 단계에서는 이 프롬프트를 사용하거나 읽거나 답안을 점검하지 않는다. AI는 사용자 답안을 대신 쓰지 않으며, 실행하지 않은 테스트·없는 AI 교정·확정되지 않은 정책을 채점 근거로 만들지 않는다. 과제 코드·테스트·설정·제출물은 수정하지 않는다.
