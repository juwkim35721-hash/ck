# 문제 정의·완료 기준

## 사용 시점
환경·규칙·기준선을 확인한 뒤, 설계나 구현을 시작하기 전에 사용한다.
요청문, README, 제공 파일, 담당자 답변을 읽어 과제의 성공 조건을 고정할 때 쓴다.
공식 안내가 제공되면 그것을 최우선 근거로 삼는다.

## 필요 입력
- [과제 루트]: 실제 과제 폴더. 준비 도구 저장소가 아닌지 확인한다.
- [남은 시간: 분]: 정의 범위와 질문 대기 한도를 정한다.
- [요구사항/파일/답변]: 원문과 출처를 구분해 제공한다.
- [제출 형식/경로]: 알려진 경우에만 제공한다.
- [이미 확인한 실행·테스트 결과]: 없으면 “미실행”으로 적는다.

입력의 대괄호 항목은 실제 정보로 바꾼다.
공식 메일이나 채점 규칙이 없으면 없는 사실을 채우지 않는다.

## 전략
먼저 요청문과 제공 자료를 읽기 전용으로 대조한다.
각 독립 요구를 R1, R2처럼 식별하고, 원문 근거와 해석을 분리한다.
사용자 문제는 “누가 무엇을 어떤 결과로 얻는가” 한 문장으로 쓴다.
각 R에는 관찰 가능한 입출력, 제약, 합격/불합격 판정 조건을 연결한다.
“빠른”, “정확한”, “친화적인” 같은 형용사는 측정값·사례·출력 규칙으로 바꾼다.
제출물은 파일명·형식·필수 내용·확인 방법이 확인된 것만 기록한다.
명시되지 않은 기능, 성능 목표, 통합, 배포는 비목표로 분리한다.
요구사항을 바꾸는 모호성만 미확인 가정으로 남기고 영향도를 표시한다.

## 기본 프롬프트
```text
$sk-define
당신은 구현 전에 문제를 정의하는 분석자다. 이 단계에서는 읽기·정리만 하고 파일을 수정하거나 구현 계획을 확정하지 마라.

[과제 루트]: [과제 루트]
[남은 시간: 분]: [남은 시간: 분]
[요구사항/파일/답변]:
[요구사항/파일/답변]
[제출 형식/경로]: [제출 형식/경로]
[이미 확인한 실행·테스트 결과]: [이미 확인한 실행·테스트 결과]

원문 근거가 있는 내용만 사용하여 다음 형식으로 답하라.
1. 사용자 문제: 사용자·목표·성공 결과를 한 문장으로 쓴다.
2. 요구사항 표: R1부터 번호를 붙이고, 원문 근거, 해석, 입력/행동, 기대 출력, 제약을 적는다.
3. 수용 기준: 각 R마다 정상 사례와 최소 한 개의 경계 또는 실패 사례를 관찰 가능한 조건으로 쓴다. 측정값이나 형식이 미정이면 “미확인”이라고 쓴다.
4. 필수 제출물: 확인된 파일/형식/경로/포함 내용을 적고, 추정은 넣지 않는다.
5. 비목표: 원문에 없는 기능·통합·배포·성능 약속을 적는다.
6. 미확인 가정: 구현 결과를 바꿀 수 있는 항목만 영향도(높음/중간/낮음)와 함께 적는다.

공식 안내 메일은 제공되지 않았다. 모델, 시험 일정, 금지 규정, 채점 방식, 문항을 추정하지 마라.
AI 사용이 허용된 단계에서만 이 분석을 사용하고, 후속 AI 금지 서술형이 시작되면 즉시 중단하라.
마지막에 다음 단계로 넘어갈 수 있는지 아래 게이트로 판정하라: 모든 R에 수용 기준이 있고, 필수 제출물이 확인되었으며, 높은 영향도 미확인은 질문 또는 보류로 표시되었는가?
```

## 심화/반증 프롬프트
```text
$sk-define
다음 문제 정의 초안을 반증하라. 읽기 전용 검토만 하며 새 요구사항을 발명하지 마라.

[과제 원문과 제공 파일]: [요구사항/파일/답변]
[문제 정의 초안]:
[문제 정의 초안]

아래 순서로 점검하라.
- R1 등 각 요구사항이 원문 근거를 갖는지, 서로 중복·충돌하지 않는지 확인한다.
- 수용 기준이 “좋게”, “정확히”, “빠르게”처럼 판정 불가능한 표현에 의존하는지 찾고, 원문으로 확정 가능한 테스트 조건만 제안한다.
- 입력 누락, 출력 형식, 오류·빈 값, 순서, 보존해야 할 기존 동작 중 원문에 언급됐지만 초안에서 빠진 것을 찾는다.
- 제출 파일·경로·형식이 사실인지, 추정인지, 미확인인지 구분한다.
- 구현 결과를 뒤집을 수 있는 가정을 영향도 순으로 최대 3개 제시한다.

출력은 “발견 사항(근거 포함)”, “수정할 수용 기준”, “질문하거나 보류할 항목”, “유지할 비목표” 순서로 쓴다.
근거 없는 채점 규칙·기한·도구 제한·완료 선언을 추가하지 마라.
AI 허용 여부가 불명확하면 공식 안내를 확인할 때까지 분석을 중단하라고 적어라.
```

## 완료 기준
- 사용자 문제, R-ID 요구사항 목록, 수용 기준, 필수 제출물, 비목표가 분리되어 있다.
- 모든 수용 기준은 관찰·테스트 가능한 결과이거나 명시적으로 미확인이다.
- 원문 근거 없는 세부 규칙과 테스트 결과를 만들지 않았다.
- 높은 영향도 미확인은 질문 또는 보류 상태로 표시했다.

## 다음 단계
완료 게이트를 통과하면 정책을 바꿀 수 있는 높은 영향도 모호성만 02-clarify로 넘긴다.
게이트를 통과하지 못하면 구현·설계를 시작하지 말고 부족한 원문, 제출 규칙, 또는 답변을 요청한다.
시간이 부족해도 요구사항을 임의 확정하지 말고 P0 수용 기준과 미확인 항목만 남긴다.

## 주의
이 단계는 기본 읽기 전용이다. 구현, 파일 수정, 배포, 제출, 외부 전송을 하지 않는다.
준비 도구 저장소를 실제 과제로 오인하지 않고 [과제 루트]의 자료만 근거로 삼는다.
후속 AI 금지 평가가 시작되면 이 문서, 프롬프트, 암기 자료의 사용을 중단한다.
