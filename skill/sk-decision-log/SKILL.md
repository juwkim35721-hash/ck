# 설계 결정·AI 교정 즉시 기록

## 목적

구현 중 생긴 설계 선택 DD#과 AI 제안·코드의 교정 사실 AI#를 짧고 검증 가능하게 남긴다.

이 기록은 후속 Q1·Q4, 제출 보고서의 설계·검증 절, 디버깅 재개에 쓸 수 있는 사실의 원천이다.

결정을 새로 만들어 내는 스킬이 아니다. 이미 관찰·선택·실행한 사실을 즉시 보존한다.

## 언제 쓰나 / 쓰지 않나

- `3.2 design ($sk-design)` 뒤 첫 S#의 구조를 확정했을 때 DD#을 남긴다.
- `4.2 implement ($sk-implement)` 중 정책·경계·오류 처리·호환성 선택을 했을 때 사용한다.
- AI가 만든 제안이나 코드에서 누락·오류·과잉 변경을 발견하고 실제로 수정 지시했을 때 AI#을 남긴다.
- `6.1 debug ($sk-debug)`에서 원인과 최소 수정이 확정됐을 때 관련 DD# 또는 AI#을 보강한다.
- 단순 포맷 변경, 이미 기록한 결정의 반복, 아직 실행하지 않은 추측은 기록하지 않는다.
- 요구사항·정책 자체가 불명확하면 결정으로 덮지 말고 → `1.3 dm-questions ($sk-dm-questions)` 또는 → `2.1 spec ($sk-spec)`으로 넘긴다.

## 입력과 사전 확인

1. 대상 S#, R#/AC/P#/A#/C#/T#, 실행한 E#를 확인한다.
2. `sk/work/DECISIONS.md`에서 마지막 DD#·AI# 번호를 확인한다.
3. `sk/work/SPEC.md`의 5절 P, 6절 A, 12절 추적표를 읽어 근거 ID를 확인한다.
4. `sk/work/PLAN.md`에서 현재 S#의 상태와 축소 결정을 확인한다.
5. AI 교정 기록 전에는 원래 제안·문제·발견 방법·수정 지시·확인 결과가 실제로 있었는지 확인한다.
6. 테스트를 실행했다면 `sk/work/EVIDENCE.md`의 해당 E#을 연결한다. 아직 실행하지 않았으면 `미검증`이라고 적는다.
7. 민감값, 토큰, 개인정보, 장황한 전체 대화·diff는 기록하지 않는다.

## 절차

1. 지금 기록할 것이 DD#인지 AI#인지 먼저 고른다.
2. DD#이면 "무엇을 고르는 선택인가"를 한 문장으로 고정한다.
3. 선택지 A/B를 실제로 고려한 범위에서만 적고, 가상의 많은 대안을 만들지 않는다.
4. 선택 근거를 R#/P#/C#/A#/T#, 파일·함수, 관찰 사실, 남은 시간에 연결한다.
5. 포기한 범위와 영향을 받는 파일·함수·호출자를 적는다.
6. 되돌릴 경계와 다음 검증 T# 또는 E#을 한 줄로 적는다.
7. AI#이면 AI의 최초 산출물에서 발견한 구체 문제를 한 줄로 적는다.
8. 발견 방법을 실제 근거로 쓴다. 예: T3 실패, 호출자 대조, P2 재확인, 실제 오류 출력이다.
9. 내가 내린 수정 지시와 실제 변경 방향을 구분 없이 짧게 적는다.
10. 실행된 테스트·증거 E# 또는 `미검증`을 적는다. 통과 여부를 꾸며내지 않는다.
11. 각 기록은 2~6줄을 목표로 하되, 필수 필드가 빠지면 한두 줄을 추가한다.
12. 기록 직후, PLAN 상태·SPEC 추적표·EVIDENCE 중 갱신할 책임이 다른 스킬에 있으면 해당 스킬로 인계한다.

### 최소 경로 — 시간이 없을 때

1. DD#: 상황, 선택, R#/P# 근거, 영향, T#/E# 계획의 5개 줄만 쓴다.
2. AI#: 문제, 발견 방법, 수정 지시, T#/E# 결과의 4개 줄만 쓴다.
3. 번호를 늘리고, 없는 실행 결과는 `미검증`으로 남긴다.
4. 즉시 현재 작업으로 돌아가되, 다음 실행 후 → `5.2 evidence ($sk-evidence)`로 E#을 보완한다.

## 판단 기준·분기

- **if** 두 구현 경로 중 하나를 택해 파일·호출자·검증이 달라진다 **then** DD#을 기록한다.
- **if** 선택이 P#를 구현한 것뿐이고 설계 대안이 없었다 **then** DECISIONS가 아니라 SPEC 추적표와 구현 기록으로 충분할 수 있다.
- **if** AI의 최초 제안이 정확했고 교정하지 않았다 **then** AI#을 만들지 않는다. AI 사용 사실 자체는 오류 기록이 아니다.
- **if** AI 제안의 문제를 발견했지만 아직 수정·검증하지 않았다 **then** 발견과 수정 지시만 기록하고 결과는 `미검증`으로 둔다.
- **if** 같은 문제를 재수정한다 **then** 기존 AI#을 지우지 말고 새 AI#으로 추가해 시간순 사실을 보존한다.
- **if** 선택의 근거가 담당자 답변과 충돌한다 **then** DD#으로 확정하지 말고 G#를 남기고 → `1.4 dm-answers ($sk-dm-log)` 또는 `1.3 dm-questions ($sk-dm-questions)`으로 간다.
- **if** 테스트가 실패한다 **then** 실패를 성공 근거로 쓰지 말고 → `6.1 debug ($sk-debug)`에 최소 재현과 E#을 넘긴다.
- **if** 남은 시간이 부족하다 **then** 선택하지 않은 개선안을 포기한 것으로 남기고 → `6.5 timebox ($sk-timebox)`에 축소 근거를 전달한다.

## 작업 노트 기록

`sk/work/DECISIONS.md`만 갱신한다. 다른 결정 블록과 `## AI 교정 기록`을 덮어쓰지 않는다.

### DD# 블록

파일 끝 또는 시간 순서상 적절한 위치에 다음을 추가한다.

```markdown
## DD<n> <결정 제목>
- 상황: <S#, 문제, 영향을 받는 계약>
- 선택지·선택: A) <안> / B) <안> → <선택한 안>
- 근거: <R#/P#/C#/A#, 코드 관찰, 시간 제약>
- 포기·영향: <포기한 범위, 파일·함수·호출자>
- 되돌림·확인: <되돌릴 지점, T# / E# / 미검증>
```

### `## AI 교정 기록`

섹션이 없으면 정확히 이 제목으로 만든 뒤 그 아래에 추가한다.

```markdown
### AI<n> <짧은 교정 제목>
- 최초 제안·문제: <AI가 제안한 것과 실제 결함>
- 발견: <T# 실패, P# 대조, 호출자 확인, 오류 출력 중 실제 방법>
- 내가 지시한 수정: <구체적인 수정 방향>
- 확인: <실행한 T#/E# 결과 또는 미검증>
```

- DD#와 AI#은 기존 최대 번호보다 1 크게 부여한다.
- `AI 교정 기록` 제목은 변경하지 않고, AI#을 DD# 블록으로 기록하지 않는다.
- "좋아 보임", "아마 통과" 같은 평가 대신 파일·함수·ID·실제 결과를 쓴다.

### 현실적인 예시

```markdown
## DD3 빈 입력을 입구에서 거부
- 상황: S2에서 R4의 빈 `userId`가 집계 로직까지 전달될 수 있음.
- 선택지·선택: A) 경계 Guard / B) 집계 중 무시 → A 선택.
- 근거: P2, T7, `src/handler.ts:parseRequest`; 호출자 오류 계약 보존.
- 포기·영향: 집계 함수 내부 추론을 포기; handler와 기존 400 응답만 영향.
- 되돌림·확인: Guard 한 블록 제거 가능; T7 실행 전까지 미검증.
```

이 예시는 형식 예시일 뿐, 실제 기록에는 실제 ID·파일·결과만 쓴다.

## 채팅 출력 형식

1. 기록 대상: DD# 또는 AI#, 연결한 S#/R#/P#/T#/E#.
2. 새로 쓴 블록: 2~6줄 요약을 그대로 제시한다.
3. 사실 상태: 실행됨·실패·미검증을 분명히 표기한다.
4. 영향: 다음에 갱신할 노트나 호출자·테스트를 한 줄로 적는다.
5. 다음 단계: 현재 상황에 맞는 하나의 프롬프트 ID와 스킬을 제시한다.

## 완료 기준

- 기록이 실제로 발생한 선택 또는 AI 교정 사실만 담는다.
- DD#에는 상황, 선택지·선택, 근거, 영향, 되돌림·확인이 있다.
- AI#에는 최초 문제, 발견 방법, 내 수정 지시, 확인 상태가 있다.
- ID 번호가 중복되지 않고 기존 기록을 지우지 않았다.
- 실행하지 않은 결과를 통과로 적지 않고 E# 또는 `미검증`이 있다.
- `DECISIONS.md`의 정확한 섹션만 갱신했다.

## 금지

- AI가 만들었다는 이유만으로 코드를 통과·안전하다고 기록하지 않는다.
- AI의 긴 원문, 전체 diff, 민감 데이터·비밀값·개인정보를 복사하지 않는다.
- 담당자 답변을 일반화하거나 A#를 P#로 승격하지 않는다.
- 실패한 테스트를 삭제·변경해 증거를 좋게 보이게 하지 않는다.
- 아직 하지 않은 실험·테스트·성능 측정을 E#처럼 기록하지 않는다.
- 과제 코드·테스트·설정·원본 데이터를 이 기록 작업의 일부로 수정하지 않는다.
- 외부 push, 배포, 제출, 업로드, 자격증명 전송을 실행하지 않는다.
