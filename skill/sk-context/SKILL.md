# 환경·규칙·기준선 확인

## 목적
과제 루트와 도구 설치 상태를 혼동 없이 확인하고, 구현 전의 실행·테스트 기준선을 남긴다.
공식 안내와 과제 파일에서 확인한 사실만 기록해 이후 단계의 잘못된 명령 실행을 막는다.
과제 파일은 읽기만 하며 이 스킬이 갱신하는 작업 노트는 `sk/work/BRIEF.md`의 `## 환경`뿐이다.

## 언제 쓰나 / 쓰지 않나
- 과제 폴더를 처음 열었을 때, 새 세션에서 작업을 재개할 때, 또는 기준선이 없을 때 사용한다.
- 설치 직후 `sk/`, `AGENTS.md`, `.agents/skills/` 상태가 정상인지 확인할 때 사용한다.
- 테스트 실패가 이미 재현되어 원인을 좁혀야 하면 → 6.1 debug (`$sk-debug`)로 넘긴다.
- 요구사항을 해석하거나 코드 구조를 상세 분석하는 일은 여기서 하지 않는다.
- 과제 코드·설정·의존성·잠금 파일을 고치거나 패키지를 설치해야 하는 상황에는 사용하지 않는다.

## 입력과 사전 확인
- 현재 쉘의 위치와 과제 안내 문서, README, 실행 안내가 있으면 그 경로를 받는다.
- 과제 루트는 `sk/` 폴더의 바로 상위 디렉터리여야 한다.
- 공식 안내에서 네트워크, 패키지 설치, 실행 가능한 명령, 포트·호스트 요구를 먼저 확인한다.
- 안내가 없으면 미확인으로 남기며 허용되었다고 추정하지 않는다.
- 비밀값, 토큰, 개인정보, 원본 데이터의 민감한 값은 화면·노트에 기록하지 않는다.

## 절차
1. 현재 위치와 과제 루트를 확정한다.
   ```bash
   pwd
   test -d sk && printf '과제 루트 후보: 확인됨\n' || printf 'sk/ 없음: 위치 재확인 필요\n'
   git rev-parse --show-toplevel 2>/dev/null || true
   ```
   Git 최상위가 달라도 `sk/`의 부모를 과제 루트로 우선하고, 불일치는 `## 환경`의 주의로 남긴다.
2. 설치 흔적을 읽기 전용으로 확인한다.
   ```bash
   test -f AGENTS.md && grep -n 'SK-KIT' AGENTS.md || true
   find .agents/skills -maxdepth 1 -mindepth 1 -type d -name 'sk-*' -print 2>/dev/null | sort
   ```
   관리 구역 또는 설치 스킬이 없으면 설치 상태를 `미확인/불완전`으로 쓰고, 임의 설치·복구는 하지 않는다.
3. 과제 도구 폴더를 제외하고 언어와 실행 단서를 수집한다.
   ```bash
   find . -path './sk' -prune -o -maxdepth 2 -type f \( -name 'README*' -o -name 'package.json' -o -name 'pyproject.toml' -o -name 'requirements*.txt' -o -name 'pom.xml' -o -name 'build.gradle*' -o -name 'Makefile' -o -name 'Dockerfile' \) -print | sort
   ```
   발견한 파일에서 언어, 런타임 버전, 실행·테스트·빌드 후보 명령을 인용 가능한 위치와 함께 적는다.
4. 금지·허용 조건을 분리한다.
   공식 문서에서 네트워크 사용, 새 패키지 설치, 데이터 수정, 포트·호스트, 제출 형식, 수정 금지 파일을 찾는다.
   문서에 없으면 `미확인`으로 표시하고 패키지 설치, 업데이트, 외부 접속을 실행하지 않는다.
5. Git 상태를 읽기 전용으로 기록한다.
   ```bash
   git status --short 2>/dev/null || true
   git diff --stat 2>/dev/null || true
   ```
   기존 변경은 사용자·기존 작업일 수 있으므로 되돌리거나 정리하지 말고 파일명만 요약한다.
6. 기준선 실행의 안전성을 판단한다.
   README나 설정에 명시된 로컬 테스트 명령이 있고, 설치·다운로드·마이그레이션·데이터 변경을 하지 않는다고 확인될 때만 1회 실행한다.
   명령이 불명확하거나 부작용 가능성이 있으면 실행하지 않고 이유와 다음 확인 행동을 기록한다.
7. 안전한 기준선 명령을 1개만 실행한다.
   ```bash
   <문서에 명시된 테스트 또는 빌드 명령>
   ```
   종료 코드, 통과·실패 수, 핵심 오류 첫 줄, 실행 여부를 기록한다.
   실패를 코드 결함으로 단정하지 말고 환경·의존성·테스트 실패를 구분해 관찰 사실로만 쓴다.
8. `sk/work/BRIEF.md`의 `## 환경`만 생성 또는 갱신한다.
   다른 섹션을 덮어쓰지 않고, 기존 행의 사실이 바뀌었을 때만 근거와 함께 갱신한다.
9. 설치 또는 루트가 막히면 사용자에게 확인할 최소 질문을 1개 제시하고, 해결 전에는 테스트를 반복 실행하지 않는다.
10. 환경이 확인되면 → 0.2 triage (`$sk-triage`)를 제안하고, 기존 코드가 있으면 이어서 → 0.3 code-map (`$sk-code-map`)을 제안한다.

## 판단 기준·분기
- if `sk/`가 현재 위치에 없으면 then 상위·하위 폴더를 무작정 탐색하지 말고 사용자가 지정한 과제 루트를 확인받는다.
- if `AGENTS.md` 관리 구역 또는 `.agents/skills/sk-*`가 없으면 then 설치 불완전으로 기록하고, 설치 명령 실행 여부는 사용자에게 맡긴다.
- if README와 설정의 명령이 다르면 then 둘을 나란히 기록하고 더 안전한 읽기 전용 명령을 우선한다.
- if 테스트가 의존성 다운로드·DB 초기화·외부 서비스 호출을 암시하면 then 실행을 중단하고 공식 허용 여부를 확인한다.
- if 기준선이 실패하면 then 실패한 명령, 종료 코드, 첫 오류를 남기고 구현 전에 → 6.1 debug (`$sk-debug`) 또는 환경 확인을 권한다.
- if 기준선이 통과하면 then 그것은 현재 상태의 관찰일 뿐 요구사항 충족 판정이 아님을 명시한다.
- if Git 변경이 있으면 then 변경 파일을 보호 대상으로 표시하고 복구·초기화 명령을 사용하지 않는다.
- 시간이 5분 미만이면 then 루트·런타임·명령 후보·금지 조건·Git 상태만 기록하고 기준선 실행은 안전할 때만 한다.

## 작업 노트 기록
`sk/work/BRIEF.md`에서 정확히 `## 환경` 섹션만 쓴다.
섹션이 없으면 아래 제목과 표를 만들고, 있으면 이 표의 해당 행만 갱신한다.

| 항목 | 확인값 | 근거·명령 | 판정·주의 |
| :--- | :--- | :--- | :--- |
| 과제 루트 | `.` 또는 확인 경로 | `pwd`, `sk/` 존재 | 경로 불일치 여부 |
| 설치 상태 | 확인됨/불완전/미확인 | 관리 구역·스킬 경로 | 설치 행동은 사용자 결정 |
| 언어·런타임 | 예: Python 3.x | 파일:줄 또는 버전 명령 | 확인 범위 |
| 실행·테스트·빌드 | 명령 후보 | README/설정 위치 | 안전성·실행 여부 |
| 기준선 | PASS/FAIL/미실행 | 명령·종료 코드·요약 | 실패 원인 미단정 |
| 네트워크·설치 | 허용/금지/미확인 | 공식 안내 위치 | 미확인은 실행 금지 |
| 포트·호스트 | 요구값/미확인 | 공식 안내·설정 | 지정 포트 유지, 웹 과제는 `0.0.0.0` 바인딩(내장 Browser 미리보기) |
| 수정 금지·보호 대상 | 파일·경로/없음 | 문서·Git 상태 | 보호 이유 |

기준선 행에는 실제로 실행한 결과만 쓴다.
`PASS`는 명령이 통과했다는 뜻이며 전체 요구사항 충족을 뜻하지 않는다.

## 채팅 출력 형식
1. **루트·설치 상태**: 과제 루트, 설치 확인 결과, 막힌 항목을 한 줄씩 말한다.
2. **실행 환경**: 언어·런타임과 문서 근거를 말한다.
3. **명령과 기준선**: 실행·테스트·빌드 후보와 실제 실행 결과 또는 미실행 이유를 표로 낸다.
4. **규칙·위험**: 네트워크·패키지·포트·보호 파일의 허용 상태를 말한다.
5. **기록**: `sk/work/BRIEF.md#환경` 갱신 여부를 말한다.
6. **다음 행동**: → 0.2 triage (`$sk-triage`), 필요 시 → 0.3 code-map (`$sk-code-map`)을 제안한다.

## 완료 기준
- 과제 루트와 도구 폴더의 관계를 확인했다.
- 설치 상태, 언어·런타임, 명령 후보, Git 상태를 근거와 함께 기록했다.
- 기준선은 안전할 때 1회 실행했거나, 미실행 이유를 명확히 남겼다.
- 네트워크·패키지 설치·포트·보호 파일의 상태를 허용/금지/미확인으로 분리했다.
- `sk/work/BRIEF.md#환경`만 갱신했고 다음 단계가 정해졌다.

## 금지
- 과제 코드, 테스트, 설정, 의존성, 잠금 파일, 데이터 파일을 수정하지 않는다.
- `sk/` 폴더를 과제 코드로 분석·테스트·린트·리팩터링하지 않는다.
- 사용자 확인 없이 패키지를 설치하거나 런타임을 업데이트하거나 네트워크에 접속하지 않는다.
- 지정 포트를 바꾸지 않는다. 바인딩은 웹 과제일 때 `0.0.0.0`(내장 Browser 미리보기용, 과제 문서 우선)이다.
- 기존 변경을 되돌리기 위한 위험한 Git 명령이나 파일 정리를 하지 않는다.
- 실행하지 않은 명령을 통과로 기록하거나 담당자·공식 안내의 사실을 추정해 쓰지 않는다.
