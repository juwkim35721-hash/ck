# 이해 재진술·최종 확인 메시지

## 목적

구현 직전, 담당자 답변과 문서에서 이해한 핵심 정책을 평이한 언어로 재진술해 오해를 마지막으로 줄인다.
이미 답한 내용을 다시 묻지 않고, H 영향 가정·범위·출력 핵심만 확인 가능하게 압축한다.
Codex는 DM을 발송하지 않는다. 사용자가 복붙해 보내고, 답변은 `sk-dm-log`로 기록한다.

## 언제 쓰나 / 쓰지 않나

- `→ 2.4 spec-gate ($sk-spec-gate)` 직전 또는 구현 착수 직전에 사용한다.
- 담당자 답변이 여러 개여서 해석을 한 번에 확인해야 할 때 사용한다.
- 구현 도중 범위·출력·예외 처리의 H 정책이 바뀌었을 때 다시 사용한다.
- 새 정책을 발굴하는 첫 DM에는 사용하지 않는다. 그때는 `→ 1.3 dm-questions ($sk-dm-questions)`을 쓴다.
- 이미 확정된 사항만 길게 반복하거나, 모든 P를 나열하는 요약 메시지에는 사용하지 않는다.

## 입력과 사전 확인

- `sk/work/DM_LOG.md`의 최근 M 블록과 `## 정책 목록 P`를 읽는다.
- `sk/work/DISCOVERY.md`의 열린 H G와 기본안 후보를 확인한다.
- `sk/work/SPEC.md`가 있으면 `## 5. 확정 정책 P`, `## 6. 가정 A`, `## 7. 열린 모호성 G`를 읽는다.
- 공식 문서, 담당자 확정 P, 테스트·코드 관찰, A의 우선순위를 다시 확인한다.
- 이미 답변으로 확정된 정책은 확인용 평이한 문장으로만 포함하며, 새 선택지를 만들지 않는다.

## 절차

1. **메시지 필요성을 판정한다.** H 가정, 상호 의존 정책, 최근 범위 변경 중 하나가 없으면 불필요한 DM을 보내지 않는다.
2. **목표를 한 줄로 정리한다.** 사용자가 이해한 업무 결과를 기술 구현이 아닌 결과 언어로 쓴다.
3. **정책을 3~5개만 고른다.** P0, H G, 출력 계약, 범위에 직접 영향을 주는 P/A만 택한다.
4. **각 규칙을 평이한 문장으로 바꾼다.** “필드 nullability” 대신 “값이 비어 있으면 제외”처럼 업무 결과를 쓴다.
5. **출력 형식을 한 줄로 쓴다.** 파일·API·목록의 핵심 필드, 빈 결과, 정렬 중 확정된 사실만 포함한다.
6. **비목표를 1~2개 넣는다.** 이번 범위에서 하지 않을 기능·데이터 변경을 구체적으로 적는다.
7. **H 가정을 명시 확인한다.** “답변 전에는 X로 진행하려 합니다. 이렇게 진행해도 될까요?”로 한 문장만 쓴다.
8. **새 질문을 분리한다.** 재진술 안에 새 정책 질문이 나오면 이 메시지를 고치지 말고 `sk-dm-questions`의 후속 질문으로 보낸다.
9. **10줄 이내로 다듬는다.** 인사·목표·규칙·출력·범위·확인 요청을 포함하되 문단을 늘리지 않는다.
10. **사용자 발송용 블록을 만든다.** 코드블록에 복붙용 문장만 넣고 내부 ID·파일명은 제거한다.
11. **DM_LOG에 M 블록을 기록한다.** 포함 P/A/G와 목적을 매핑하고, 보내기 전 상태를 `발송 대기`로 둔다.
12. **답변 후 변환 경로를 제시한다.** 확인된 A는 `→ 1.4 dm-answers ($sk-dm-log)`에서 P로 승격한다.

### 포함·제외 선택 규칙

| 포함한다 | 제외한다 |
| :--- | :--- |
| P0 결과를 바꾸는 확정 정책 | P2 기능·스타일 선호 |
| H 영향 가정과 되돌릴 수 없는 선택 | 이미 여러 번 확정된 세부 표현 |
| 빈 결과·정렬·오류처럼 외부 결과에 보이는 규칙 | 내부 함수명·라이브러리·테스트 방식 |
| 이번 범위 밖 항목 | 평가·채점·내부 ID |

### 10줄 구성 틀 (`sk/templates/DM_QUESTION_TEMPLATES.txt` 4절 M11과 같다)

```text
안녕하세요. 구현 전 제가 이해한 내용을 짧게 확인 부탁드립니다.
목표: <업무 결과 한 줄>
- <확정 정책 1>
- <확정 정책 2>
- <확정 정책 3>
결과는 <출력 형식 핵심>으로 제공하겠습니다.
이번에는 <비목표 1>과 <비목표 2>는 포함하지 않습니다.
아직 <H 가정>은 <기본안>으로 진행하려 합니다. 이렇게 진행해도 될까요?
다른 해석이 있으면 알려주시면 바로 반영하겠습니다.
```

### 현실적 예시

```text
안녕하세요. 구현 전 제가 이해한 내용을 짧게 확인 부탁드립니다.
목표: 유효한 거래만 기준으로 일별 집계 결과를 제공하는 것입니다.
- 수량이 비어 있으면 해당 거래는 집계에서 제외합니다.
- 수량이 음수이면 요청을 오류로 처리합니다.
- 취소된 거래는 마감 시각과 관계없이 집계에서 제외합니다.
- 합계가 같으면 거래 ID 오름차순으로 정렬합니다.
결과가 없으면 빈 목록으로 반환하겠습니다.
이번에는 원본 데이터 수정과 신규 화면 추가는 포함하지 않습니다.
아직 시간대 기준은 문서에 없어 UTC로 진행하려 합니다. 이렇게 진행해도 될까요?
```

## 판단 기준·분기

- 모든 H 항목이 P로 확정됐고 범위가 바뀌지 않았으면 최종 확인 DM은 선택 사항이다. 기다리느라 구현을 지연하지 않는다.
- H A가 하나라도 외부 출력·금액·데이터 손실을 바꾸면 확인 요청을 포함한다.
- 담당자가 “맞습니다”라고 답하면 그 메시지에 실제 포함된 문장만 P 근거로 승격한다.
- 담당자가 한 문장을 고치면 나머지 문장이 자동 확정된 것으로 보지 않는다. 수정 범위를 분리한다.
- 담당자가 새 정책을 추가하면 새 P 또는 G로 분리하고, 충돌 여부를 `sk-dm-log`에서 확인한다.
- 답이 없으면 A를 명시한 상태로 `READY-WITH-ASSUMPTIONS` 후보로 진행할 수 있으며, 반드시 되돌릴 지점을 남긴다.
- 시간이 5분 이하이면 목표·H A·출력만 포함한 5줄 확인 메시지로 축소한다.

## 작업 노트 기록

`sk/work/DM_LOG.md`에 새 `## M<n> …` 블록을 추가한다. 기존 M과 `## 정책 목록 P`를 덮어쓰지 않는다.

```markdown
## M3 2026-..-.. 구현 전 이해 재진술 — 발송 대기
- 목적: P1, P2, P4와 A1의 최종 해석 확인
- 관련 정책·가정: P1, P2, P4, A1
- 관련 G: G5
- 발송자: 사용자 직접 DM 예정
- 메시지:
  [복붙용 최종 문구]
- 확인 요청: A1 시간대 기본안
- 답변 원문: (수신 후 원문 그대로 추가)
- 상태: 발송 대기
```

- 답변이 오면 원문을 M 블록에 보존하고 `→ 1.4 dm-answers ($sk-dm-log)`으로 정책을 전환한다.
- 확인된 A의 승격은 `DM_LOG.md#정책 목록 P`와 `SPEC.md#5. 확정 정책 P`에 추가하고, `SPEC.md#6. 가정 A`의 상태·근거를 갱신한다.
- `SPEC.md`의 다른 표준 절을 임의로 재작성하지 않는다. 정식 통합은 `→ 2.1 spec ($sk-spec)`가 한다.

## 채팅 출력 형식

1. 확인 DM이 필요한 이유와 포함한 P/A/G 목록
2. 복붙용 최종 메시지 1개를 `text` 코드블록으로 제시
3. 사용자가 직접 보내야 한다는 안내
4. M 번호와 답변 수신 뒤 처리 경로
5. 답이 없을 때의 A·되돌릴 지점·게이트 판정 영향
6. 다음 행동: `→ 1.4 dm-answers ($sk-dm-log)` 또는 `→ 2.4 spec-gate ($sk-spec-gate)`

## 완료 기준

- 목표 1줄, 핵심 정책 3~5개, 출력 핵심, 비목표 1~2개가 평이하게 정리됐다.
- H 가정은 “이렇게 진행해도 될까요?”로 명시됐고 새 정책 질문과 섞이지 않았다.
- 메시지는 10줄 이내이며 내부 ID·기술 구현 용어·평가 질문이 없다.
- DM_LOG에 새 M 블록과 P/A/G 매핑이 기록됐고 사용자가 발송할 역할이 분명하다.
- 답변·무응답의 다음 처리 경로가 있다.

## 금지

- 담당자가 이미 확정한 모든 세부사항을 길게 재질문하거나 답을 재촉하지 않는다.
- 새 정책 발견 질문을 재진술 메시지에 섞지 않는다.
- 담당자 확인 전 A를 P로 표기하거나, 답이 없는데 확인됐다고 쓰지 않는다.
- 과제 코드·테스트·데이터를 수정하거나, DM으로 민감값·비밀값을 전송하지 않는다.
- 공식 문서와 P의 충돌을 “이해 확인” 문구로 숨기지 않는다. 먼저 G와 후속 질문으로 분리한다.
