# 예외·경계·불변식 방어

## 역할

구현의 정상 흐름을 넓히지 말고, 계약을 깨는 실패를 위험 순으로 재현·방어하라.
공식 규칙을 우선하고 AI 사용이 허용된 단계에서만 작업하라.
AI 금지 서술형이 시작되면 프롬프트와 이 스킬 사용을 즉시 중단하라.

## 입력 확인

다음을 확보하라.

- 실제 과제 루트와 승인된 수정 범위
- 남은 시간, 변경된 요구사항 ID, 실행 가능한 기준선 명령
- 입력·출력·오류·상태 계약과 실제 호출자
- 권한, 재시도, 시간 제한의 명시 규칙 또는 부재 사실

입력이나 정책 근거가 없으면 읽기 전용으로 확인한 뒤 정확히 부족한 정보만 질문하라.
공식 메일·채점·제한·기본값을 추정하여 만들지 마라.

## 절차

1. 기존 테스트와 최소 정상 흐름을 실행해 기준선 결과를 기록하라.
2. 각 변경 경계의 입력, 변경 상태, 성공 출력, 실패 전달 경로를 짧게 적어라.
3. 다음 중 적용 가능한 위험만 고르고, 되돌리기 어려운 영향을 먼저 검사하라.
   - 권한 우회, 데이터 손실, 잘못된 상태 확정
   - 중복·재시도·경합에 의한 멱등성 또는 불변식 위반
   - 필수 키, 타입, 단위, 범위의 계약 위반
   - 숫자 문자열·손상 레코드 같은 형식 불일치와 동점 시 비결정적 정렬
   - 없는 대상, timeout, 의존 실패에서 숨겨진 오류
   - 빈 값, 0, 음수, 긴 값, 순서의 경계 의미 훼손
   - 문서화된 웹 요청 경계에서만 호스트 바인딩·CORS의 허용 출처 불일치
4. 위험 하나마다 최소 재현 입력 하나와 계약 근거가 있는 기대 동작을 정하라.
5. 수정 전에 재현이 실제로 실패하는지 확인하라. 실패하지 않으면 결함으로 보고하지 마라.
6. 원인과 가장 가까운 경계만 최소로 수정하고 회귀 assert를 추가하거나 실행하라.
7. 새 반례, 관련 기존 테스트, 정상 흐름을 재실행하고 정확한 명령과 결과를 보존하라.

## 분기

빈 값·0·음수가 업무상 유효하면 falsy 검사로 거절하지 말고 계약에 따라 처리하라.
웹 서버의 호스트나 CORS는 공식 요구·배포 환경·실제 미리보기 근거가 있을 때만 검사·수정하고, 임의의 바인딩 값을 강제하지 마라.
정책 선택이 필요한데 근거가 없으면 동작을 임의 확정하지 말고 질문, 보류 지점, 잔여 위험을 보고하라.
테스트가 불안정하거나 외부 의존으로 실행 불가하면 통과로 바꾸지 말고 재현 조건과 미검증 사유를 남겨라.
시간이 부족하면 저위험 개선과 리팩터링을 중단하고 P0 방어·회귀 실행·잔여 위험 보고를 우선하라.
적용할 경계가 없으면 코드와 계약을 확인한 근거 및 해당 없음 이유를 기록하라.

## 출력 형식

각 검사에 `재현 입력 | 기대 동작과 근거 | 수정 또는 해당 없음 이유 | 실행 명령·결과 | 회귀 테스트`를 제시하라.
마지막에 수정 파일, 미검증 항목, 정책 질문, 잔여 위험을 분리해 요약하라.

## 완료 기준

재현된 결함마다 최소 수정과 회귀 검증이 연결되어야 한다.
기준선·경계·정상 흐름의 실제 결과와 적용 불가 사유를 숨기지 말아야 한다.

## 금지 행동

검증되지 않은 기본값을 넣지 마라.
예외를 무조건 무시하거나 성공으로 바꾸지 마라.
원본 데이터, 기존 테스트, 사용자 관련 없는 변경을 삭제·덮어쓰지 마라.
전면 리팩터링, 외부 push·배포·제출, 인증의 임의 추가·제거를 하지 마라.
