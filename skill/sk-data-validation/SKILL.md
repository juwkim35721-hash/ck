# 데이터 정합성 독립 검산

## 목적

원본과 결과 파일의 행 수·결측·범위·집계를 비교하고 구현과 다른 방법으로 핵심 수치를 재계산한다.
P#의 제외·변환·반올림·정렬 정책이 결과에 실제로 반영됐는지 독립 근거로 검증한다.
불일치를 숨기지 않고 재현 가능한 E#로 남겨 디버깅에 넘긴다.

## 언제 쓰나 / 쓰지 않나

- CSV, JSON, JSONL을 입력 또는 결과로 다루는 과제의 P0 구현 뒤에 쓴다.
- 집계, 필터, 정제, 변환, 순위, 파일 생성이 있는 유형 A 과제에서는 필수에 가깝다.
- API나 UI만 있고 비교할 데이터 파일이 없으면 → 5.4 api-contract ($sk-api-contract) 또는 → 5.5 ui-smoke ($sk-ui-smoke)를 쓴다.
- 데이터 처리 규칙이 모호하면 검산 전에 → 1.2 ambiguity ($sk-ambiguity)와 → 1.3 dm-questions ($sk-dm-questions)로 보낸다.
- 이 스킬은 원본·결과 데이터를 수정하거나 정규화하지 않는다.

## 입력과 사전 확인

1. `sk/work/SPEC.md`의 5절 P와 10절 데이터 계약을 읽는다.
2. 원본 파일, 결과 파일, 제외 목록 또는 오류 로그의 실제 경로를 확인한다.
3. 파일 형식과 인코딩을 확인하고 대용량·민감 데이터면 집계만 기록할 방법을 정한다.
4. `sk/work/EVIDENCE.md`의 최신 E#와 결과를 만든 코드 상태를 확인한다.
5. 데이터 파일이 다른 프로세스에서 생성 중이면 완료 여부를 확인하고 부분 파일을 검산하지 않는다.

## 절차

1. 대사 범위를 선언한다.
   입력 파일과 결과 파일, 비교 단위(전체 행·키·그룹·금액), 적용할 P#와 T#를 적는다.
2. 두 파일을 각각 감사한다.
```bash
python3 sk/snippets/data_audit.py <원본_파일>
python3 sk/snippets/data_audit.py <결과_파일>
```
   행 수, 컬럼, 필드별 결측, 숫자 최소·중앙·최대·음수·0, 텍스트 고유값·중복을 비교한다.
3. 감사 스니펫의 한계를 선언한다.
   CSV·JSON·JSONL만 지원하고 파일 전체를 메모리에 읽는다.
   숫자 판정은 값의 50% 초과가 숫자로 변환되는지에 따른 휴리스틱이며 고정 결측 토큰만 센다.
   손상 JSONL 줄은 중단할 수 있고 TSV·Excel·Parquet은 지원하지 않으므로 다른 읽기 도구로 바꾼다.
4. 독립 계산 방식을 선택한다.
   구현이 pandas이면 Python `csv` 또는 `json` 표준 라이브러리의 짧은 읽기 전용 계산을 쓴다.
   구현이 SQL이면 내보낸 결과를 표준 라이브러리로 합산한다.
   구현과 같은 함수·쿼리·변환 모듈을 재호출해서 기대값을 만들지 않는다.
5. 독립 계산의 입력·필터·키를 명시한다.
   유효·제외 행은 P#와 데이터 계약의 결측·중복 규칙으로 정의한다.
   정책이 불명확하면 기본 처리로 채우지 말고 G# 후보로 남긴다.
6. 먼저 전체 행 수를 대사한다.
   정책상 변환이 1:1이면 `입력 행 = 결과 행 + 제외 행`을 확인한다.
   집계·조인이면 유니크 키·그룹 수·단계별 수를 맞춘다.
7. 제외 사유별 수를 대사한다.
   예: `결측 2건, 중복 1건, 범위 오류 3건`처럼 P# 사유마다 입력 표본 수와 결과 로그 수를 비교한다.
8. 핵심 수치를 재계산한다.
   총합, 평균, 그룹별 개수, 최대·최소, 순위별 값 중 R/AC가 요구하는 것을 최소 하나 이상 별도 계산한다.
   반올림은 계산 마지막인지 항목별인지, 단위 변환은 전후 어느 시점인지 P#대로 확인한다.
9. 결과 스키마를 확인한다.
   열 이름·타입 표현·null 표현·필수 열, 정렬, 동점 순서, 빈 결과 표현을 SPEC 10절과 대조한다.
10. 대표 경계 표본을 눈으로 대조한다.
    빈 값, 0, 음수, 동점, 중복 키 중 실제 존재하는 1~3건만 골라 P#에 따라 확인한다.
    민감 식별자·원본 값은 기록하지 않고 행 번호나 마스킹된 키를 쓴다.
11. 불일치를 분류한다.
    행 수 차이, 정책 위반, 독립 계산 차이, 스키마 차이, 감사 도구 한계 중 하나로 분류한다.
12. 실제 실행 근거를 기록한다.
    감사 명령, 독립 계산 방법, 핵심 수치, 코드 상태, 판정을 → 5.2 evidence ($sk-evidence) 형식 E#로 기록한다.
13. 다음 행동을 결정한다.
    불일치는 재현 자료와 E#를 붙여 → 6.1 debug ($sk-debug)로 넘긴다.
    정책·계약의 빈칸은 G#로 연결해 → 1.3 dm-questions ($sk-dm-questions) 또는 → 2.2 io-contract ($sk-data-contract)로 넘긴다.

## 판단 기준·분기

- if 입력과 결과가 1:1 변환이고 행 수 식이 맞지 않는다 → 차이 수가 작아도 FAIL이다.
- if 집계라서 행 수 식이 성립하지 않는다 → 키·그룹·합계 대사로 바꾸고 이유를 기록한다.
- if 값 차이가 부동소수점 오차일 수 있다 → SPEC·P#의 반올림 규칙 또는 허용 오차가 있을 때만 그 기준으로 판단한다.
- if 감사가 메모리 부족·지원하지 않는 형식으로 실패한다 → 실패 출력을 E#에 적고 스트리밍 등 독립 방법으로 대체한다.
- if 감사 출력의 상위값이 민감정보를 노출한다 → 값을 기록·채팅에 옮기지 말고 개수·범위·마스킹만 남긴다.
- if 제외 이유가 결과에 없어 대사 불가하다 → 실패라고 추정하지 말고 해당 P#를 `미검증`으로 둔다.
- if 시간이 부족하다 → 전체 행 수, 핵심 총합 하나, P0 제외 수, 결과 정렬만 최소 경로로 확인한다.

## 작업 노트 기록

`sk/work/EVIDENCE.md`의 `## 실행 기록`에 실제 감사와 독립 계산마다 다음 열을 유지해 E# 행을 추가한다.
`E# | 시각 | 명령·작업 디렉터리 | 대상 R/T | 기대 | 실제 결과 요약 | 판정 | 코드 상태`.

실제 결과 요약에는 필요한 사실을 압축해 쓴다.
`원본 100행, 결과 96행, P4 제외 4행, 독립 합계 1250.0 = 결과 합계 1250.0`.
`data_audit.py`의 원문 상위값·개별 민감 행·비밀값은 넣지 않는다.

수용 테스트와 연결할 수 있으면 `sk/work/SPEC.md`의 `## 12. 추적표`에서 기존 열
`R | AC | T | 구현 위치 | 증거 E | 상태`의 증거 E와 상태를 실제 E#로만 갱신한다.

## 채팅 출력 형식

1. `대상과 정책`: 원본·결과 경로, R/T, 적용 P#.
2. `감사 결과`: 행 수·스키마·결측·범위 비교와 도구 한계.
3. `독립 검산`: 구현과 다른 계산 방법, 대사 식, 핵심 수치.
4. `정책 확인`: 제외 사유, 반올림·단위, 정렬·동점의 실제 관찰.
5. `판정·증거`: E#, PASS·FAIL·미검증 및 코드 상태.
6. `다음 행동`: 불일치 또는 모호성의 정확한 인계 ID·스킬.

## 완료 기준

- 원본과 결과에 실제 감사 또는 형식에 맞는 대체 점검을 실행했다.
- 행 수 또는 집계 구조에 맞는 대사 식과 독립 계산이 있다.
- P#의 제외·변환·반올림·정렬 중 적용되는 항목을 확인했다.
- 감사 스니펫의 형식·메모리·휴리스틱 한계를 결과와 함께 밝혔다.
- 모든 일치·불일치 판정이 E#의 실제 명령과 수치에 연결된다.
- 불일치는 FAIL 또는 미검증으로 남기고 디버그·명세 단계로 인계했다.

## 금지

- 원본 데이터나 결과 파일을 고쳐서 행 수·합계를 맞추지 않는다.
- 구현의 집계 함수나 동일 쿼리를 다시 불러 독립 검산이라고 주장하지 않는다.
- 감사 출력의 개인정보·식별자·민감 상위값을 채팅이나 노트에 그대로 적지 않는다.
- 지원하지 않는 형식의 감사 실패를 데이터 통과로 해석하지 않는다.
- 실제 실행 없이 행 수·합계·PASS를 만들어 기록하지 않는다.
- 과제 코드·테스트·설정·의존성을 검산 과정에서 수정·추가하지 않는다.
