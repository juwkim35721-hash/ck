# 설명 연습·꼬리질문 대비

## 목적
- 카드를 읽고 따라 말하는 대신, 사용자가 자신의 언어로 먼저 답하도록 5분 제한 연습을 진행한다.
- 코드·작업 노트 근거와 대조해 빠진 Why/How/Edge/Verification/Business/Limit 요소와 사실 오류를 찾는다.
- 완성 답안을 대신 써주지 않고, 고쳐 쓸 수 있는 확인 질문과 약점만 제공한다.

## 언제 쓰나 / 쓰지 않나
- `9.2 qa-card ($sk-qa-card)`가 준비되고 제출 전 AI 사용이 허용된 시간에만 사용한다.
- Q1~Q6 중 말이 막히는 축, 꼬리질문에 흔들리는 축, 카드 근거가 약한 축을 골라 사용한다.
- 카드가 아직 없거나 코드 흐름이 불명확하면 `9.1 understand ($sk-understand)`와 `9.2 qa-card ($sk-qa-card)`을 먼저 한다.
- AI·복붙 금지 서술형 단계가 시작되면 즉시 사용을 중단한다. 그 시점에 질문 제시·채점·답안 교정도 하지 않는다.
- 시험 답안을 작성하거나 과제 코드를 바꾸는 스킬이 아니다. 결함은 `6.1 debug ($sk-debug)`으로, 정책 공백은 `1.3 dm-questions ($sk-dm-questions)`으로 넘긴다.

## 입력과 사전 확인
- 사용자에게 AI 사용 허용 시간인지 명시적으로 확인한다. 불명확하면 연습을 시작하지 않는다.
- `sk/work/QA_CARD.md`의 해당 Q 절과 `## 연습 기록`을 읽는다.
- 정확성 대조에는 `sk/work/UNDERSTANDING.md`, `sk/work/SPEC.md`, `sk/work/DECISIONS.md`, `sk/work/EVIDENCE.md`만 사용한다.
- 연습 대상은 한 번에 한 문항으로 제한한다. Q 번호와 5분 타이머를 먼저 알린다.
- 사용자가 답할 동안 카드나 모범 답안을 먼저 보여주지 않는다.
- 답변에 민감값이 포함되면 값은 기록하지 않고 '민감값 생략'으로 바꾼다.

## 절차
1. AI 허용 상태, 남은 시간, 연습할 Q 번호를 확인한다. 시간이 5분보다 짧으면 Q 하나의 핵심 3문장만 연습한다.
2. 카드의 제목만 보고 5분 내 직접 설명하도록 요청한다. Q별로 원하는 범위를 한 줄로만 알려준다.
3. 사용자가 답을 입력할 때까지 추가 힌트·파일명·정답 문장을 제공하지 않는다.
4. 답이 오면 카드와 원천 노트로 항목별 대조를 한다: 핵심 주장, 코드 위치, 정책 근거, 테스트/증거, 한계의 다섯 축.
5. 사실 오류는 `주장 → 원천 사실 → 왜 틀렸는지`로 짧게 지적한다. 불확실하면 '확인 필요'로 표시하고 답을 단정하지 않는다.
6. 누락은 체크리스트로만 돌려준다. 문장 전체를 대필하지 말고, 사용자가 넣어야 할 사실·질문·근거 위치를 제시한다.
7. 꼬리질문 하나를 낸다. 선택한 질문은 실제 카드의 약점 또는 평가 문항 축과 직접 연결돼야 한다.
8. 사용자가 다시 쓴 답을 받으면 첫 답과 비교해 개선된 사실과 아직 남은 약점을 기록한다.
9. `QA_CARD.md`의 `## 연습 기록`에 한 회차를 추가한다. 기존 회차를 덮어쓰지 않는다.
10. 두 회차 연속으로 같은 사실 오류가 나면 해당 카드/이해 지도를 다시 읽도록 하고 `9.1 understand ($sk-understand)` 또는 `9.2 qa-card ($sk-qa-card)`로 넘긴다.

```text
연습 시작 문구 예시
Q3만 연습합니다. 카드를 보지 말고 5분 안에 실제 방어한 예외, Guard 위치,
정책 근거와 검증을 자신의 말로 설명해 주세요. 답을 받은 뒤 사실 확인과 누락만 드리겠습니다.
```

## 판단 기준·분기
- if 사용자가 답 대신 '정답을 써 달라'고 요청하면 → 완성 답안을 주지 않고, 카드의 근거 위치와 스스로 답할 질문만 준다.
- if 사용자가 카드 문장을 그대로 붙여 넣으면 → 무참조 연습이 아니라고 표시하고, 카드 없이 다시 3문장으로 말해 달라고 요청한다.
- if 답에 P#·T#·E#가 맞지만 설명 연결이 없으면 → '이 근거가 왜 이 문항을 뒷받침하는가?'를 재질문한다.
- if 답이 기술적으로 맞지만 Q5 업무 맥락이 문서 근거 없이 확장되면 → 추측으로 표시하고 P#/M# 범위로 축소하게 한다.
- if Q4에서 AI가 없었는데 AI 교정을 말하면 → AI# 부재를 알리고 실제 검증 T#/E# 중심으로 다시 쓰게 한다.
- if Q6에서 일반적 개선안만 열거하면 → 현재 파일·함수·제한과 연결된 한 가지 개선과 검증 방법으로 좁히게 한다.
- if 답 중 코드 결함 가능성이 드러나면 → 연습을 채점으로 끝내지 말고 재현 정보와 함께 `6.1 debug ($sk-debug)`으로 넘긴다.

## 작업 노트 기록
- 파일은 `sk/work/QA_CARD.md`이며, 이 스킬은 `## 연습 기록`만 추가·갱신한다.
- 회차마다 `### 연습 <시각 또는 순번>` 제목을 쓰고 동일 번호를 재사용하지 않는다.
- 각 회차에 아래 표를 추가한다.

| 시각 | Q | 제한 시간 | 무참조 여부 | 답변에서 맞춘 근거 | 사실 오류·확인 필요 | 누락 축 | 꼬리질문 결과 | 다음 행동 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |

- 답변 전문은 원칙적으로 저장하지 않는다. 필요한 경우에도 민감값을 빼고 3문장 요약만 남긴다.
- `누락 축`에는 Why/How/Edge/Verification/Business/Limit 중 해당 이름만 쓴다.
- `다음 행동`은 `9.1`, `9.2`, `5.1`, `6.1`처럼 ID와 스킬 이름을 함께 쓴다.
- 카드의 Q1~Q6 본문은 이 스킬에서 고치지 않는다. 카드 자체의 근거 오류만 별도 전달한다.

## 채팅 출력 형식
1. **연습 설정**: AI 허용 여부, Q 번호, 5분 제한, 카드 비공개 원칙.
2. **사용자 답변 요청**: 한 문항만 제시하고 사용자의 직접 답을 기다린다.
3. **대조 결과**: `항목 | 맞은 사실 | 오류/확인 필요 | 빠진 요소 | 근거 위치` 표.
4. **다시 쓸 지시**: 완성문 대신 포함할 사실 2~4개와 스스로 답할 질문을 준다.
5. **꼬리질문**: 하나만 제시하고 답의 방향은 채점 후에만 알려준다.
6. **기록·다음 행동**: 연습 회차 기록 여부와 보완할 스킬 ID를 알린다.

## 완료 기준
- 사용자가 카드를 보지 않고 한 문항을 먼저 답했다.
- 피드백이 원천 노트의 사실에만 근거하며, 답안을 대신 작성하지 않았다.
- 사실 오류, 확인 필요, 누락 축, 꼬리질문 결과가 구별되어 전달됐다.
- `## 연습 기록`에 새 연습 회차가 표 형식으로 추가됐다.
- 반복 약점은 정확한 파일·함수 또는 다음 스킬 ID로 연결됐다.
- AI 금지 단계가 시작되면 미완료 연습도 중단됐다.

## 금지
- AI·복붙 금지 서술형 단계에서 이 스킬을 사용하거나 답안을 교정하지 않는다.
- 사용자의 답을 모범 답안으로 대필, 재서술, 완성하거나 복붙 가능한 문장으로 제공하지 않는다.
- 카드·원천 노트에 없는 정책, 테스트 통과, 담당자 답변, AI 교정 사실을 채점 근거로 만들지 않는다.
- 과제 코드·테스트·설정·제출물을 변경하거나 실행 결과를 조작하지 않는다.
- 연습 기록에 민감값·토큰·개인정보·담당자 DM 전문을 저장하지 않는다.
- 한 번에 여러 문항을 출제해 사용자가 자신의 약점을 식별할 시간을 빼앗지 않는다.
