# 입출력·데이터 계약 확정

## 목적

과제의 파일·함수·API·화면 경계에서 입력, 정상 출력, 오류 출력을 증거와 함께 계약으로 정리하라.
`sk/work/SPEC.md`의 `## 10. 입출력·데이터 계약`만 갱신하고, 관찰값과 아직 결정되지 않은 정책을 분리하라.
데이터 파일이 있으면 감사 결과를 근거로 쓰되, 감사 도구의 휴리스틱을 공식 스키마로 오인하지 마라.

## 언제 쓰나 / 쓰지 않나

- 2.1이 R/P/C/A를 통합한 다음, 구현·설계 전에 데이터 또는 API 경계를 명확히 할 때 쓴다.
- CSV, JSON, JSONL, HTTP API, CLI 입출력, 함수 인자·반환값, UI 폼에 적용한다.
- 데이터 이상이 발견돼 처리 정책을 물어야 할 때는 → 1.3 dm-questions (`$sk-dm-questions`)로 넘긴다.
- 정책 답변을 P#로 해석할 때는 → 1.4 dm-answers (`$sk-dm-log`)를 쓴다.
- 테스트 표를 작성할 때는 → 2.3 acceptance (`$sk-acceptance`)를 쓰고, 실제 테스트·코드는 만들지 않는다.

## 입력과 사전 확인

1. `sk/work/SPEC.md`의 `## 1. 목표`, `## 3. 요구사항 R`, `## 4. 제약 C`, `## 5. 확정 정책 P`, `## 6. 가정 A`, `## 7. 열린 모호성 G`를 읽어라.
2. `sk/work/BRIEF.md`의 `## 환경`, `## 코드 지도`를 읽고 실제 진입점·테스트·샘플 경로를 확인하라.
3. 공식 문서, 타입 선언, 호출자, 기존 테스트, 샘플을 순서대로 읽되 모두 읽기 전용으로 다뤄라.
4. 분석 대상 파일의 형식과 크기를 확인하고, 민감값이 있으면 값·상위범주·식별자를 출력하지 않을 계획을 세워라.
5. 기존 SPEC의 0~9, 11~14절을 읽어 연결만 확인하고 수정 대상은 10절로 한정하라.

## 절차

1. 경계를 `입력자 → 검증 지점 → 핵심 처리 → 출력 소비자`로 한 줄씩 나열하라.
2. 각 경계의 증거를 공식 문서, P#, 타입·호출자, 테스트, 샘플 순으로 모으고 파일:줄 또는 문서 절을 붙여라.
3. 입력 계약 표에 `필드 | 타입 | 필수 | 허용 범위·형식 | 결측 표현 | 단위·시간대 | 예시 | 상태·근거`를 작성하라.
4. 키가 있으면 단일·복합 키, 고유성, 중복 요청/레코드 처리, 멱등성 여부를 별도 행으로 기록하라.
5. 시간 값은 형식, 시간대, 포함·제외 경계, 파싱 실패 동작을 각각 확인하고 추정하지 마라.
6. 정상 출력 계약 표에 `필드 | 타입 | 계산·변환 | 정렬 | 반올림·단위 | null 표현 | 빈 결과 | 근거`를 작성하라.
7. 오류 계약 표에 `조건 | 상태 코드·예외 | 본문/메시지 | 필드 오류 | 부분 성공 | 재시도 | 근거`를 작성하라.
8. API이면 `메서드 | 경로 | 요청 본문·파라미터 | 성공 상태·본문 | 오류 상태·본문 | 호환성 제약` 표도 추가하라.
9. 파일 데이터가 CSV·JSON·JSONL이면 아래처럼 원본을 바꾸지 않고 감사하라.
10. `python3 sk/snippets/data_audit.py <파일>`을 실행하고 종료 코드와 요약만 기록하라.
11. 감사의 행 수, 컬럼, 결측 수, 숫자 min/median/max, 음수·0, 텍스트 중복 수·상위값을 관찰값으로 옮겨라.
12. 상위값에 개인정보·비밀값이 있을 수 있으면 값 자체는 기록하지 말고 개수·범주화된 사실만 남겨라.
13. 감사 결과에서 결측, 음수, 0, 중복, 예상 밖 범위가 발견되면 R/P 근거가 있는지 확인하라.
14. 근거 없는 처리 방식은 만들지 말고 10절의 미확인 항목에 G 후보로 적어 영향·예시·기본안·결정 시점을 남겨라.
15. 감사 도구는 CSV/JSON/JSONL만 지원하며 TSV·Excel·Parquet은 지원하지 않음을 기록하고, 해당 형식은 과제의 기존 도구나 읽기 전용 표본 검토로 대체하라.
16. 이 도구는 파일 전체를 메모리에 읽으므로 큰 파일에서는 실행 전에 크기·환경 제약을 확인하고, 실행하지 못하면 사유를 기록하라.
17. 숫자 판정은 50% 초과 값이 파싱될 때의 휴리스틱이고 결측 토큰도 고정 목록이므로, 결과 타입을 계약으로 승격하지 마라.
18. 손상 JSONL은 한 줄에서 중단될 수 있으므로 실패 줄과 도구 한계를 기록하고 임의로 고치지 마라.
19. 각 계약 항목을 `확정`, `관찰됨이나 미확정`, `미확인`으로 표시하라.
20. 2.3이 만들 수 있도록 정상·경계·실패 사례의 입력과 기대 관찰 후보를 계약 끝에 남겨라.
21. `## 10. 입출력·데이터 계약`에 조사 시각, 범위, 근거, 도구 실행 여부와 한계를 함께 기록하라.

## 판단 기준·분기

- 공식 문서와 P#가 있으면 샘플보다 우선하고, P#와 문서가 충돌하면 G#와 1.3 질문으로 처리하라.
- 샘플 한 행만 있으면 관찰된 값으로만 기록하고 누락·중복·정렬·오류 규칙을 미확인으로 남겨라.
- 호출자가 보내는 값과 타입 선언이 다르면 둘 다 출처로 제시하고 호환성 위험을 G#로 남겨라.
- 데이터가 없거나 접근 불가하면 없는 사실을 분명히 쓰고, 계약을 추측해 완성으로 표시하지 마라.
- API 서버가 실행 중이지 않아도 서버를 임의로 띄우지 말고 문서·코드·테스트 근거만으로 분석하라.
- 오류 응답을 관찰하지 못했으면 성공 응답 형식을 오류 형식으로 확대하지 마라.
- 시간이 부족하면 필수 키, 타입, 필수성, 단위, 시간대, 키·중복, 출력 정렬·빈 결과, 오류 계약부터 확정하라.

## 작업 노트 기록

`sk/work/SPEC.md`의 `## 10. 입출력·데이터 계약`만 추가·갱신하라.
다음 하위 제목과 표를 사용하라.

| 하위 제목 | 반드시 포함할 내용 |
| --- | --- |
| `### 범위·근거` | 대상 경계, 출처, 조사 시각, 감사 실행 여부 |
| `### 입력 계약` | 필드·타입·필수·범위·결측·단위·예시·상태 |
| `### 키·중복·시간 규칙` | 식별 기준, 중복, 정렬, 시간 형식·시간대 |
| `### 출력 계약` | 스키마, 변환, 정렬, 반올림, null·빈 결과 |
| `### 오류 계약` | 조건, 상태/예외, 본문, 부분 성공, 재시도 |
| `### API 계약` | 해당할 때 메서드·경로·상태 코드·본문 |
| `### 데이터 감사와 한계` | 수치 요약, 민감값 처리, 도구·표본 한계 |
| `### 미확인과 테스트 입력 후보` | G#/A# 연결, 정상·경계·실패 사례 |

예: `amount | number | 필수 | 0 이상(문서 18행) | null 불가 | KRW | 1200 | 확정`처럼 증거 상태를 한 행에 붙여라.
예: `POST /items | 201 + id | 400 + field 오류 | M3-2 | 관찰됨이나 미확정`처럼 API의 미확정 부분을 숨기지 마라.
새 G 후보는 10절에만 적고 → 2.1 spec (`$sk-spec`)으로 넘겨 `## 7. 열린 모호성 G`에 편입하게 하라.

## 채팅 출력 형식

다음 순서로 보고하라.

1. 분석한 경계와 신뢰도별 근거
2. 확정된 입력·출력·오류 계약의 핵심
3. 감사 명령·실행 결과 요약 또는 미실행 사유와 한계
4. 새 G 후보/A#와 데이터 위험, 필요한 DM 여부
5. 다음 단계: → 2.3 acceptance (`$sk-acceptance`), H 영향이면 → 1.3 dm-questions (`$sk-dm-questions`)

## 완료 기준

- 10절에 각 대상 경계의 입력, 정상 출력, 오류 출력 계약이 분리되어 있다.
- 필드의 타입·필수성·범위·결측·단위·시간, 키·중복, 정렬·빈 결과가 확정 상태와 근거로 구분돼 있다.
- 데이터 감사의 실행 결과 또는 미실행 사유와 CSV/JSON/JSONL·메모리·휴리스틱 한계가 기록돼 있다.
- 감사 이상 징후가 근거 없는 정책으로 바뀌지 않았으며 필요한 G#가 연결돼 있다.
- 다음 단계가 T#로 변환할 수 있는 정상·경계·실패 입력 후보를 찾을 수 있다.

## 금지

- 과제 코드, 원본 데이터, 기존 테스트, 설정, 제출물을 수정·삭제·정제·재저장하지 마라.
- 감사 도구의 출력·중앙값·상위값만으로 비즈니스 정책, 타입, 데이터 품질을 확정하지 마라.
- 민감한 원문값·식별자·비밀값을 채팅 또는 `sk/work/`에 복사하지 마라.
- TSV·Excel·Parquet을 이 도구로 지원된다고 주장하거나 손상 JSONL을 조용히 건너뛰지 마라.
- 임의 포트·호스트로 서버를 띄우거나 외부 호출·제출·배포·push를 하지 마라.
- 실행하지 않은 감사나 API 결과를 통과·확정으로 기록하지 마라.
