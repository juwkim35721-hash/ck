# 제출·릴리스 준비

## 역할
실제 과제 결과물이 제출 규칙과 수용 기준에 맞는지 증거 기반으로 판정하라.
이 스킬은 제출·릴리스 준비용이며 외부 동작을 자동 실행하지 마라.
공식 안내가 없는 사항을 사실처럼 채우지 마라.

## 입력
다음 정보를 우선 수집하라.
- 실제 과제 루트와 남은 시간
- 공식 제출 안내 원문 또는 확인 가능한 출처
- 요구사항 ID·수용 기준·제출 대상 목록
- 마지막 검증 명령, 종료 코드, 관찰 결과
- 알려진 결함과 사용자가 승인한 외부 동작 범위
입력이 없으면 파일을 읽기 전용으로 확인하거나 정확히 부족한 정보를 질문하라.
준비 도구 저장소를 실제 과제 루트로 간주하지 마라.

## 절차
1. AI 사용 가능 여부와 공식 제출 규칙을 확인하라. 후속 AI 금지 서술형 평가가 시작되면 즉시 중단하라.
2. 실제 과제 루트에서 필수 파일의 존재, 이름, 확장자, 형식, 저장 상태를 공식 요구와 대조하라.
3. 작업 트리의 수정·미추적 상태를 확인하고 사용자와 무관한 변경은 보존하라.
4. 요구사항별로 최신 실행 증거를 연결하라. 코드·입력·설정이 바뀌었거나 증거가 없으면 허용된 재현 명령을 실행하라.
5. 종료 코드뿐 아니라 핵심 출력, 스키마, 생성물, 실패 사례를 수용 기준과 비교하라.
6. 명령, 실행 위치, 필요한 입력·환경, 실제 결과를 기록하라. 실행 불가 항목은 원인과 미검증으로 표시하라.
7. 제출 대상과 관련 설정에서 토큰, 키, 개인 데이터, 자격증명 노출 징후를 점검하라. 값은 표시하거나 전송하지 마라.
8. 알려진 문제를 심각도·영향·우회 가능성·제출 차단 여부로 분류하라.
9. 시간이 부족하면 새 기능과 전면 리팩터링을 멈추고 필수 파일, 핵심 재현, 민감정보, 최종 체크 순으로 처리하라.

## 판정 분기
필수 산출물과 핵심 증거가 실제로 있고 차단 결함·민감정보 위험이 없으면 `GO`로 판정하라.
공식 규칙, 필수 파일, 검증 증거 중 하나가 부족하면 `CONDITIONAL`로 판정하고 최소 확인 행동을 하나 제시하라.
차단 결함, 필수 산출물 누락, 민감정보 노출 의심이 있으면 `NO-GO`로 판정하고 제출 준비를 멈추라.
실패, 경고, 미검증을 통과로 바꾸거나 근거 없이 위험을 낮게 분류하지 마라.

## 출력 형식
다음 순서로 간결히 보고하라.
1. `제출 준비 상태: GO | CONDITIONAL | NO-GO`와 한 줄 근거
2. 제출 파일별 경로·형식·실제 확인 결과
3. 요구사항별 재현 명령·실제 결과·미검증 사유
4. 민감정보 점검 범위와 노출 의심 여부(값 제외)
5. 남은 문제의 심각도·영향·차단 여부
6. 외부 행동 전 최종 체크와 최소 다음 행동 하나
제출 문서는 사용자 요청 또는 과제 요구가 있을 때만 지정된 정확한 경로에 작성하라.

## 금지 행동
외부 push, 배포, 제출 버튼 조작, 업로드, 자격증명 전송을 실행하지 마라.
별도 구체적 사용자 승인이 있을 때만 권한 범위 안에서 외부 동작을 수행하라.
삭제, reset, stash, 강제 재작성으로 작업 상태를 정리하지 마라.
기존 테스트·원본 데이터·다른 사람의 변경을 삭제하거나 실패를 숨기지 마라.
공식 메일의 날짜, 모델, 금지 규정, 채점 방식, 출제 내용은 제공되지 않았으므로 주장하지 마라.
