# 환경·규칙·기준선 확인

## 역할

- 코드·설정·데이터를 바꾸기 전에 작업 경계를 사실로 고정하라.
- 준비 도구 저장소와 실제 과제 저장소를 절대로 같은 것으로 가정하지 마라.
- 제공되지 않은 공식 안내나 시험 규칙을 추정하지 마라.

## 입력

- 실제 과제 루트 후보, 사용자 지시, 제공된 과제 문서와 공식 답변을 받으라.
- 남은 시간과 허용된 명령·도구 정보를 받되, 없으면 미확인으로 표시하라.
- 비밀값이 포함될 수 있는 파일이나 환경 변수가 있음을 전제하라.

## 절차

1. 현재 위치와 실제 과제 루트 후보를 읽기 전용으로 비교하라.
2. Git 최상위 경로가 확인되면 근거로 기록하되, 그것만으로 과제 루트를 확정하지 마라.
3. `~/sk`는 준비 도구로 취급하고 명시적 지시 없이는 과제 루트로 채택하지 마라.
4. 사용자 지시, 과제 문서, 적용 범위의 지침 파일을 출처별로 읽고 충돌을 표시하라.
5. 공식 안내가 없으면 AI 허용 범위, 일정, 채점, 제출 규칙을 미확인으로 남겨라.
6. 프로젝트 파일에서 언어, 패키지 관리자, 기존 실행·테스트 명령 후보를 찾아 근거를 기록하라.
7. 명령의 설치, 다운로드, 생성, 서버 기동, 데이터 변경 가능성을 먼저 판단하라.
8. 부작용이 없다고 확인된 기존 검사만 실행하고 정확한 명령, 종료 상태, 핵심 결과를 남겨라.
9. 안전성을 확인할 수 없는 명령은 실행하지 말고 미실행 사유와 필요한 확인을 남겨라.
10. 자격증명·토큰·개인정보가 의심되는 값은 열거나 출력하지 말고 경로 또는 유형만 표시하라.
11. 작업 트리의 기존 변경은 사용자와 무관한 변경으로 보존하고 원인을 추측하지 마라.

## 분기와 중단

- 실제 과제 루트 후보가 없거나 서로 충돌하면 수정 없이 최소 질문 하나를 하고 중단하라.
- 적용 규칙이 결과나 행동을 바꿀 정도로 불명확하면 그 규칙의 출처를 질문하고 다음 단계로 넘기지 마라.
- 공식 규칙이 AI 사용을 금지하거나 AI 금지 서술형이 시작되면 즉시 중단하라.
- 비밀값 노출, 외부 로그인, 제출·배포·push가 필요한 행동은 수행하지 말고 사용자 승인으로 넘겨라.
- 이 단계에서 구현, 리팩터링, 의존성 설치, 환경 변경, 새 테스트 작성은 하지 마라.

## 출력 형식

다음 항목을 짧은 사실 목록으로 반환하라.

- 실제 과제 루트: 경로와 확인 근거 또는 미확인 사유
- 적용 규칙과 금지: 출처별 사실과 미확인 항목
- 도구 가용성: 확인한 도구·명령과 근거
- 기준선: 정확한 명령·종료 상태·결과 또는 미실행 사유
- 수정 금지 범위와 비밀정보 위험: 값 없는 경로·유형만 포함
- 다음 확인 항목: 최대 세 개와 진행 게이트

## 완료 기준

- 과제 루트, 적용 규칙, 기준선이 각각 증거 또는 명확한 미확인 사유와 연결되어야 한다.
- 실행하지 않은 검사를 통과로 표현하지 마라.
- 다음 단계가 요구사항 정의인지, 질문 대기인지, 중단인지 하나로 명시하라.
