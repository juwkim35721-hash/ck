# SK 해커톤 하네스

이 구역은 `python3 sk/scripts/install.py`가 과제 루트 `AGENTS.md`에 넣은 공통 작업 규칙이다. 공식 대회 안내와 과제 문서가 항상 우선한다. AI 사용이 허용된 단계에서만 적용한다.

## 0. 위치 약속

- 이 `AGENTS.md`가 있는 폴더가 **과제 루트**다. Codex는 여기서 실행된다.
- `sk/`는 과제 루트에 클론한 준비 도구다. **과제 코드가 아니다.** 분석·테스트·린트·리팩터링·제출물 판단 대상에서 제외하고, `sk/work/` 밖의 `sk/` 파일은 수정하지 않는다.
- 작업 노트는 `sk/work/`에만 쓴다: `BRIEF` `DISCOVERY` `DM_LOG` `SPEC` `PLAN` `DECISIONS` `EVIDENCE` `REVIEW` `UNDERSTANDING` `QA_CARD` (.md). 단계 사이의 기억은 대화가 아니라 이 파일들에 둔다. 다른 스킬이 맡은 섹션은 덮어쓰지 않는다.
- 자료 위치: 프롬프트 `sk/prompts/<단계>/`, 템플릿 `sk/templates/`, 스니펫 `sk/snippets/`, 상세 안내 `sk/playbooks/MASTER_GUIDE.md`.

## 1. 우선순위

공식 대회 안내·과제 문서 > 사용자의 현재 지시 > 담당자 확정 답변(`SPEC.md` P#) > 기존 테스트·코드의 관찰된 동작 > 가정(A#) > 이 하네스. 공식 문서와 담당자 답변이 충돌하면 조용히 고르지 말고 모호성(G#)으로 기록하고 확인 질문을 제안한다.

## 2. 단계와 스킬

| 단계 | 스킬 (순서대로) |
| :--- | :--- |
| 0 착수 | `$sk-context` → `$sk-triage` → `$sk-code-map` |
| 1 발굴·담당자 DM | `$sk-clarify-loop`(스캔·질문·답변 반영을 라운드로 반복, 권장) 또는 `$sk-requirements` → `$sk-ambiguity` → `$sk-dm-questions` → (사용자가 DM 전송·답변 붙여넣기) → `$sk-dm-log` → `$sk-dm-confirm` |
| 2 명세 | `$sk-spec` → `$sk-data-contract` → `$sk-acceptance` → `$sk-spec-gate` |
| 3 계획·설계 | `$sk-plan` → `$sk-design`, 수시로 `$sk-decision-log` |
| 4 구현 루프 | `$sk-build-loop`(슬라이스 하나를 착수 점검→RED→GREEN→방어→검증까지 한 바퀴, 권장) 또는 슬라이스마다 `$sk-test-first` → `$sk-implement` → `$sk-harden` → `$sk-verify` / `$sk-evidence` |
| 5 검증 특화 | `$sk-data-validation`, `$sk-api-contract`, `$sk-ui-smoke` |
| 6 막힐 때 | `$sk-debug`, `$sk-unstuck`, `$sk-rollback`, `$sk-resume`, `$sk-timebox` |
| 7 리뷰 | `$sk-review` → `$sk-compliance` |
| 마무리 | `$sk-understand` → `$sk-retrospect` → `$sk-report` → `$sk-qa-card` → `$sk-deliver` → `$sk-qa-drill` |

사용자가 스킬을 지정하지 않아도 상황에 맞는 스킬을 제안한다. 단계를 건너뛰면 그 이유와 위험을 한 줄로 말한다.

## 3. 구현 전 원칙 (가장 중요)

- `sk/work/SPEC.md`의 `## 0. 상태`가 `READY` 또는 `READY-WITH-ASSUMPTIONS`가 되기 전에는 과제 코드를 수정하지 않는다. 사용자가 명시적으로 요청하면 예외로 하되 그 사실을 기록한다.
- 결과를 바꾸는 모호성은 추측하지 않는다: G#로 기록 → DM 질문 초안 → 답이 늦으면 기본값·근거·되돌릴 지점이 있는 가정 A#로 진행.
- **Codex는 담당자에게 DM을 보낼 수 없다.** 복붙용 메시지만 만들고, 사용자가 보낸다. 담당자 답변을 지어내거나 추측해서 확정 정책으로 쓰지 않는다.
- 담당자 답변은 원문을 `DM_LOG.md`에 보존하고, 테스트 가능한 규칙 P#("조건 → 동작")으로 바꾼 뒤 `SPEC.md`에 반영한다.

## 4. 구현·검증 원칙

- 한 번에 한 슬라이스(S#), 최소 변경. 공개 인터페이스·함수 서명·출력 스키마·필수 파일명·지정 포트·기존 테스트를 유지한다.
- 근거 없는 처리 규칙을 새로 만들지 않는다. 무조건적인 기본값 치환, 광범위한 예외 무시, 인증 해제, 테스트 삭제·약화로 오류를 숨기지 않는다. 과제에 없는 API·UI·ML 구조를 새로 만들지 않는다.
- 웹 서버·UI 과제는 내장 Browser 미리보기에서 보이도록 지정 포트로 `0.0.0.0`에 바인딩해 실행한다(과제 문서가 다르게 정하면 과제 문서 우선). 같은 환경의 로컬 검사는 `127.0.0.1`로 한다. 웹 과제가 아니면 서버를 만들지 않는다.
- 의미 있는 실행 뒤에는 `EVIDENCE.md`에 E#로 기록한다. 실행하지 않은 것을 통과라고 말하지 않는다. 코드가 바뀌면 이전 증거는 STALE이다. HTTP 상태 코드나 화면 표시만으로 업무 결과가 맞다고 판단하지 않는다.
- 설계 결정은 DD#, AI가 만든 코드·제안을 고친 일은 AI#로 `DECISIONS.md`에 즉시 남긴다. 보고서와 후속 6문항의 근거가 된다.
- 같은 오류가 2회 반복되거나 diff가 계속 커지면 수정을 멈추고 `$sk-unstuck`을 따른다.

## 5. 금지

- 외부 push·배포·제출 버튼·업로드·자격증명 전송.
- `git reset --hard`, `git clean`, `git stash`, 강제 checkout, 원본 데이터·기존 테스트 삭제 또는 약화.
- Codex 업데이트, 모델·시스템 설정 변경, 허용되지 않은 패키지 설치·네트워크 사용(필요하면 사용자 확인).
- 무관한 리팩터링·대규모 포맷 변경, 지정 포트 변경.
- 비밀값·토큰·개인정보·민감한 원본 데이터 값 출력, 비공개 과제·데이터를 외부에 올리기.
- AI 사용이 금지된 단계(후속 서술형 등)가 시작된 뒤의 답안 작성·교정 보조.

## 6. 보고 형식

작업이 끝날 때마다 한국어로 짧게: ① 한 일과 변경 파일 ② 실행한 명령과 실제 결과(E#) ③ 갱신한 작업 노트 ④ 남은 위험·미검증 ⑤ 다음 행동 1개(프롬프트 ID와 스킬).

## 7. 시간 감각

착수부터 명세 동결까지는 짧게 끝낸다(대략 시작 후 40분 이내, 답이 늦으면 가정으로 진행). 남은 시간이 약 40분이면 새 기능을 줄이고 마무리 단계로 넘어간다. 남은 15분에는 새 기능·리팩터링을 하지 않고 제출 점검만 한다. 정확한 시간표는 공식 안내를 따른다.
